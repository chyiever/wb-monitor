## 界面与操作

主页面顺序为 `View / eDAS / FIP / Setting`，信号检测 Tab3 仍默认隐藏，可在 Setting 中打开，打开后位于 FIP 后面。

1. `View` 保留 FIP/eDAS 联合绘图、空间时间图、PSD 及现有曲线选择。
2. `eDAS` 左侧滚动参数区合并原采集软件的采集参数、相位参数、原 Setting 参数、原 Time-Space 参数和共享设置。START/STOP 与 FIP 页的 eDAS 采集按钮使用同一主控链路。
3. eDAS 页右侧上方为统一波形，数据源可选择 PHASE/RAW 或 Monitor 的选定位置趋势；PSD 可关闭；时空图位于下方。波形、PSD、时空图使用同一布局列，固定左轴宽度，波形 X 范围链接时空图。
4. PHASE 的波形与 PSD 使用选定位置的完整采样率数据；时空图有独立显示降采样，不能用其降采样后像素计算全带宽 PSD。Monitor 显示选定空间点的时间趋势，并按该趋势的实际时间间隔估算 PSD。
5. PHASE 单上传通道可以共享到 View/联合存储。RAW 及多上传通道保留硬件独立采集/存储能力，共享链路不开放。RAW 模式沿用原软件的显示语义；时空图主要面向 PHASE。
6. `共享数据至 View / 联合存储` 只控制路由，关闭共享后仍可独立采集和保存 DAS，采集序号继续计时。重新打开共享后，间隔显示为缺口，不把停用时间压缩成连续数据。
7. 共享周期必须与 FIP 包时长一致；采集期间锁定共享周期、通道范围及降采样参数。修改这些参数应先停止采集。
8. DAS 独立 SAVE、路径、BIN/BZ 格式和分文件设置位于 eDAS 页；FIP 页保留 FIP 通信、两路对齐、FIP 独立存储及联合存储。旧 eDAS TCP 地址、端口和重复独立存储入口隐藏，不启动 eDAS socket。

时间对齐继续使用原有包序号机制。进程内共享消除了网络发送/接收延迟，但不提供新的硬件同步触发能力；同序号不等于物理采样时刻已被校准。现场应核对两路启动及触发、周期、采样率和缺口记录。

## 数据链路

```text
PCIe DLL → AcquisitionThread（完整原始块）
            ├─ 原始 int32 → 独立 BIN/BZ 后台保存
            ├─ 有界共享队列 → 同周期聚合 → float32 弧度矩阵
            │                 → 有界本机邮箱 → 原 EDASManager
            │                    ├─ 对齐协调器 + FIP → 联合后台保存
            │                    └─ 原后台绘图 → View
            └─ 最新显示快照 → eDAS 页波形/PSD/时空图
```

共享矩阵按 `phase_count * pi / 32767` 转为弧度，与原 TCP 接收的量纲一致。通道优先存放，标记只读；保存原始 DAS 的链路保持 int32，不受显示滤波或共享降采样影响。联合文件元数据新增 DAS 通道起点、空间步长与单位。

`edas_hardware` 使用包内相对导入，与 wb-monitor 的配置、日志和主窗口模块隔离；DLL 在版本目录 libs 下，参数保存在本版本 `config/edas_last_params.json`。两个版本可从任意当前工作目录通过各自 run.py 启动。

## 存储改动与边界

- 独立 BIN 及联合 BIN 用 NumPy 连续视图的 `memoryview` 写入，避免对大数组额外调用 `tobytes()` 复制完整 payload。
- 兼容联合 BIN 的 DAS float64 转换按最多 512K 元素的小块执行，避免一次扩展出整块 1.2 GB 数组。
- 联合文件先写 `.bin.part`，完成 flush/fsync 后原子改名；失败的部分文件不标记为成功文件，联合游标仅在成功后推进。
- 独立 BIN 在分文件和停止关闭时 flush/fsync；原有尾包、顺序与 CRC/分文件测试保留。
- 共享入队预算 1 GiB、本机邮箱预算 1 GiB、单个共享周期最多 1 GiB。聚合中的数组引用另有至多一个周期的工作集；各预算不是整进程 RSS 的总上限。
- 对齐缓存预算固定为 2 GiB，不再按采样速率无限扩大。联合待写数据触及预算时报告过载并停止采集。绘图及独立保存还有各自预算，部署应保留足够内存，建议实际监控峰值 RSS。
- 原独立保存按字节估算队列容量；队列拒绝块或后台写盘错误会触发明确故障并停止采集。停止不能挽回已经拒绝的块，因此故障必须视为本次采集不完整，不能报告为无损成功。
- 停止时排空已接受的共享完整周期与联合请求；联合尾部即使不足常规文件间隔也写出。共享的不足一个周期的尾部会明确记录；独立 DAS 保存保留其原始块。
- 压缩依赖在创建工作线程前检查，避免缺少 zstandard 导致退出排空挂住。BZ/NPZ/gzip 不作为 600 MB/s 的已验证选择。

## 联合格式

| 选项 | DAS 数据 | FIP 数据 | 标记与兼容性 |
|---|---|---|---|
| bin32（内置版默认） | float32 弧度 | float64 | `FIPeDAS2` / `wb-monitor-joint-bin-v2`，需新版回放源码 |
| bin | float64 弧度 | float64 | `FIPeDAS1`，兼容旧版回放 |
| npz / h5 | 沿用现有后端 | 沿用现有后端 | 高速场景需另行实测压缩成本 |

bin32 的 float32 约有 7 位十进制有效数字。它保留共享矩阵中的 float32 数值，但不等于原始 int32 计数的逐位保存；需要原始计数时同时使用 eDAS 页的独立原始存储。FIP 数据类型与现有存储保持不变。

`fipedasREAD/src/fipedas_read/data_loader.py` 已同时支持两种魔数与记录宽度。旧 dist EXE 未重打包，不能用旧 EXE 回放 bin32；使用本次更新的源码运行回放工具。旧解析器会因新魔数拒绝 v2，避免将 float32 错读为 float64。

## 600 MB/s 评估

MB 按十进制计量。测试目录位于 E 盘，使用触及真实文件的合成负载，每种模式 10 秒等效采集数据，DAS 输入 600 MB/s，单块 60 MB。独立保存按 0.1 秒节奏输入；联合保存以最快速度写入；文件完成包含 fsync。各模式使用临时目录，完成后移除测试数据。

测试未连接采集卡，未包含真实 FIP 输入；联合测试使用 DAS-only 帧及缺失标志。小规模端到端测试另行覆盖 FIP+DAS 成对联合保存和回读。实际部署的 FIP 带宽、其他磁盘负载和驱动开销还需计入。

| 测试 | 实际写入量 | 总耗时 | 结果 |
|---|---:|---:|---|
| DAS 独立 BIN，600 MB/s 节奏 | 6 GB | 10.047 s | 丢块 0、连续性缺口 0、队列峰值 1 块，结束排空 31 ms |
| 旧联合 bin/float64，最快写入 | 12 GB | 9.672 s | 输出约 1240.7 MB/s，折合 DAS 输入 620.35 MB/s，余量小 |
| 独立 BIN + 旧联合 bin | 18 GB | 10.984 s | 平均输出 1638.75 MB/s，低于 600 MB/s 输入所需约 1800 MB/s，不能据此认定可长期稳定 |
| 新联合 bin32，最快写入 | 6 GB | 5.000 s | 输出约 1200 MB/s，约为目标 DAS 输入的两倍 |
| 独立 BIN + 新联合 bin32 | 12 GB | 10.063 s | 原始输入无丢块/缺口、队列峰值 1 块，结束排空 47 ms；含结束开销平均输出 1192.49 MB/s |

新格式将该场景的理论磁盘需求从约 1.8 GB/s 降至约 1.2 GB/s，再加 FIP 的实际输出量。短测支持本次 600 MB/s 节奏；不能据此承诺长时间持续写入。SSD 缓存耗尽、接近满盘、热降速、杀毒扫描及其他进程负载都可能改变结果。换到其他盘符时需重新测试。原始 JSON 结果保存在本目录的 `storage_benchmark_261021.json` 与 `storage_benchmark_bin64_261021.json`。

复测命令（会实际写入数 GB，完成后清理自己的临时数据）：

```powershell
python src/tools/benchmark_storage.py --directory E:/scratch/wb-test --seconds 10 --joint-format bin32 --report result.json
```
