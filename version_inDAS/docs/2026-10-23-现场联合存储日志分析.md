## 代码原因与修复

1. 旧 `np.array([同形状多帧], dtype=object)` 会生成带空间/时间维度的 object 数组，把每个数值转成 Python 标量，再 pickle 压缩。改为一维 object 容器，元素为原数值 ndarray，保留精度、减少对象与序列化开销。保留旧 NPZ 字段，新旧读取代码均可按帧访问。
2. 旧逻辑写盘期间持续积压，结束后将全部未保存帧装进单个重试请求；提前刷盘阈值无法限制既有积压。增加连续前缀上限 256 MiB，正常、重试、停止排空共用；通道/采样率变化边界仍单独分文件；成功才推进游标，不因分块丢帧。
3. NPZ 改为临时 `.npz.part` 写完后重命名，异常清理临时文件，不把不完整归档作为成功产物。
4. 前一版 dev2 已有双路缓存超限保护及原始异常传递，补齐旧现场版本中仅 FIP 持续输入时的无限增长路径。此次保留这些保护，不通过增加内存上限掩盖持续吞吐不足。
