# wb-monitor 内置 eDAS 版本使用说明

版本：**v_inDAS_261021**。集成版本使用 `master2/dev2` 分支；本文及近期功能更新仅提交到 **dev2**。更新时间：2026-10-23。

软件将 PCIe-7821 eDAS 上位机与 wb-monitor 合并在同一进程，提供 eDAS 独立采集、FIP 独立通信和两路联合运行。相邻 `version_exDAS` 为外置 eDAS TCP 版本，阶段版本 `v_exDAS_261021`，对应 `master1/dev1`。

## 1. 安装和启动

在 `version_inDAS` 目录执行：

```powershell
python -m pip install -r requirements.txt
python run.py
```

无采集卡时，可使用软件生成的 eDAS 仿真数据：

```powershell
python run.py --simulate
```

仿真模式替换 eDAS 硬件数据源，FIP 仍使用真实 TCP 接口，需要外部 FIP 发送端才能收数。硬件模式需要 Windows、匹配采集卡的驱动及 `libs/pcie7821_api.dll`。启动脚本将工作目录固定在本版本目录，两个版本分别维护参数和日志。

每次启动恢复上次保存的参数，**不会自动启动通信或采集**。首次使用先检查硬件、FIP 网络、数据共享、存储路径和分段设置，再选择运行入口。

## 2. 三种运行模式与启停顺序

默认页面顺序：Tab1 **View**、Tab2 **eDAS**、Tab3 **FIP**、Tab4 **Setting**。Setting 中启用旧检测页后会多出一个名为 `Tab3` 的可选页面，Setting 的位置随之顺延；该旧页面名称不代表 FIP 页。

| 入口 | 操作及结果 |
| --- | --- |
| Tab2 eDAS 的开始采集 | 只启动本机 eDAS，不启动 FIP。可独立绘图和保存 DAS 数据；可与已启动的 FIP 同时运行。 |
| Tab2 eDAS 的停止采集 | 停止 eDAS 并排空其尾部数据，不停止 FIP。 |
| Tab3 FIP 的通信按钮 | 启动/停止 FIP TCP 服务及处理链路，不启动/停止 eDAS。启动服务后需等待 FIP 发送端连接。 |
| Tab1 View 的 Start | 按下表处理当前状态，建立联合运行顺序。重复点击不会叠加启动任务。 |
| Tab1 View 的 Stop | 取消所有等待中的联合启动；先停止并排空 eDAS，再停止 FIP。 |

**Start 的状态规则：**

| 点击前状态 | 执行顺序 |
| --- | --- |
| eDAS 和 FIP 都未运行 | 启动 FIP 服务器监听 → 等待 LabVIEW 客户端连接成功 → 等待至少 1 s → 启动 eDAS。未连接时不启动 eDAS。 |
| 只有 eDAS 在运行 | 停止两路并完成停止处理 → 等待至少 1 s → 启动 FIP 监听 → 等待客户端连接成功 → 等待至少 1 s → 启动 eDAS。 |
| 只有 FIP 在运行 | 停止两路并完成停止处理（旧 TCP 连接会断开）→ 等待至少 1 s → 重新监听 → 等待客户端重新连接 → 等待至少 1 s → 启动 eDAS。 |
| eDAS 和 FIP 都在运行 | 保持当前运行，不停止、不重启、不重置对齐状态；Start 显示为不可重复操作。 |

等待使用 Qt 精确定时器，GUI 可继续响应；系统繁忙时实际间隔可能超过 1 s。连接等待不设自动启动超时：允许操作员稍后运行 LabVIEW。倒计时期间断连立即取消计时并继续等待连接，重新连接后重新计满 1 s；重复连接通知不重置正在进行的倒计时。Stop、窗口关闭、FIP 停止或监听失败均取消后续启动。eDAS 启动失败时提示检查采集卡及参数，FIP 保持监听，可单独停止或重试。

推荐操作：先点击本软件 Tab1 Start，看到“监听中”后运行 LabVIEW VI；客户端连接成功后，本软件自动延时 1 s 启动 eDAS，由硬件原有输出脉冲触发 FIP。LabVIEW 程序及原来的 8 字节包头/数据体协议维持原样，无 READY 消息，也不会等待首包才启动 eDAS。

界面阶段：**监听中**＝服务器已启动、等待客户端；**已连接**＝真实 TCP 连接已建立，联合启动进入 1 s 延时；**等待触发**＝等待硬件触发后 FIP 首包，不代表确认硬件已布防或已触发；**已收数据**＝收到完整 FIP 包。前几个阶段为黄色提示，收到新鲜数据后才显示绿色；操作员等待连接不会被误报为接收超时，eDAS 启动后仍按首包/后续数据超时检查。

本次只确认 TCP 连接，不确认 LabVIEW 硬件初始化已完成。请让 LabVIEW 保持原有外触发采集流程，并确保硬件能在连接后的等待期内准备好。软件的 1 s 延时不是物理同步或采样时钟同步的证明。联合运行后断连不会自动再次触发 eDAS；需要重新联合采集时先 Stop，再 Start，并让客户端重新连接。

## 3. 软件架构与数据流

```text
run.py → src/main.py（应用生命周期、管理器绑定、退出清理）
                  │
                  ├─ ui/integrated_window.py：四页 GUI、参数快照、联合启停、状态面板
                  ├─ edas_hardware/：PCIe DLL / 仿真、相位处理、eDAS 绘图、独立保存
                  ├─ das/：本机共享数据接收、eDAS 管理与联合显示接口
                  ├─ fip/：TCP 接收、定点解码、处理、绘图、FIP 独立存储
                  └─ alignment/：两路包对齐、联合数据分发（联合写盘实现在 das/）

PCIe / 仿真 → eDAS 采集线程 ─┬→ 独立 DAS 保存（原始 int32，按 Save DS）
                            ├→ Tab2 波形 / PSD / 时空图
                            └→ 共享裁剪、降采样、弧度转换
                                → 进程内有界队列 → EDASManager ─┐
FIP 发送端 → TCP 服务 → Q40.24 解码 → FIP 处理管理器 ────────────┤
                          └→ FIP 独立保存                      │
                                                             ↓
                                              包序号 / 周期对齐
                                                   ├→ View 绘图
                                                   └→ 联合存储
```

eDAS 与 wb-monitor 之间通过本机共享对象和有界队列传递数据，**无需 eDAS TCP 连接**。`LocalDASSource` 保留管理器需要的接收接口，但不监听网络端口。FIP 仍通过 TCP 进入软件。

三个保存入口分别控制独立 DAS、独立 FIP、联合数据。绘图刷新、显示滤波与显示降采样用于显示链路；独立 DAS 的 Save DS、共享降采样、FIP 保存降采样和联合保存降采样分别作用于各自路径，不能互相替代。联合 DAS 数据来自共享后的数据，不等于完整原始采集卡数据。

对齐依据每次通信会话归一化后的包序号与配置周期。启动先后、重连和缺包会影响对齐，需查看 FIP 页的对齐状态及序号差。软件对齐不等同于两台设备具备共同硬件时钟或触发。

## 4. Tab1：View 联合显示和运行控制

### 4.1 曲线、绘图与状态

- **曲线选择**：为两条曲线选择 Off、DAS Channel、FIP1 或 FIP2；DAS 源需填写有效 CH。FIP2 需要实际配置并接收到双传感器数据。Off 关闭相应曲线。
- **绘图参数设置…**：打开详细绘图窗口；只有“应用并保存”才更新参数。取消或点击窗口外会放弃草稿。
- **存储参数设置…**：配置联合保存，详见第 8 节。
- **Start / Stop**：联合运行控制，按第 2 节状态规则执行。

运行状态区包括：

| 显示项 | 含义 |
| --- | --- |
| Fiber Length | 与 eDAS 页一致：Points × 0.4 m；超过 10 km 后用 km、保留 2 位小数，否则用 m、保留 1 位小数。 |
| 连续运行时长 | 任一路开始后计时；两路全部停止后保留该次时长，下一次启动重新计时。单路停止而另一路继续时不清零。 |
| eDAS / FIP 指示灯 | 结合采集/通信状态、实际数据进度、超时与错误显示状态。服务启动但未收数时不能视为数据正常。 |
| 存储指示灯 | 结合保存开关、成功完成文件和实际写盘错误判断。 |
| 磁盘剩余空间 | 已启用存储路径所在磁盘的余量；每 5 s 查询一次，不扫描历史目录。 |
| 已存储文件数 | 本次打开软件后成功完成的联合、FIP 和 DAS 文件数；不含历史文件及正在写入的文件。 |

状态颜色：灰色为未运行/未启用，黄色为等待数据或文件完成，绿色为数据有进展/文件完成，红色为异常、超时或磁盘不可用。判断异常时应结合日志和计数，不只看按钮颜色。

### 4.2 绘图参数窗口

| 小页 | 参数用法 |
| --- | --- |
| FIP 绘图 | 设置滤波开关、频段、阶数、相位展开、时间降采样及处理目标传感器。频段需符合有效采样率范围。 |
| DAS 绘图 | 设置 View DAS 曲线的显示滤波频段和阶数。 |
| 显示与刷新 | 设置时间窗口、FIP/eDAS 刷新周期、每曲线最大点数，以及时域、PSD、时空图和刷新开关。减少点数/刷新频率可降低显示负担。 |
| PSD | 控制两路 PSD、Welch 时间窗口和重叠比例。窗口越长，频率分辨率越细，也需要更多数据。 |
| 坐标轴 | 设置手动 X/Y 及 PSD Y 范围；关闭手动范围后恢复自动缩放。 |
| 时空图 | 设置 CH 范围、总时间窗、移动步长、时间/空间降采样、配色、去基线、自动色标或手动上下限。 |

## 5. Tab2：eDAS 采集、绘图和独立保存

### 5.1 主区按钮和摘要

**开始采集 / 停止采集**只控制 eDAS。**独立保存开关**控制 DAS 文件写入，**共享到 View / 联合存储**控制内部数据分发；关闭共享不停止 eDAS 采集、绘图或独立保存。

点击 **采集参数设置…** 编辑基础采集、硬件、相位处理、读取块/共享周期；**独立存储参数…** 位于“DAS 独立存储”栏；**共享与显示参数…** 位于“共享与显示”栏。后两类参数已从采集窗口分离。参数窗口外点击或取消会放弃草稿，只有 **应用并保存** 通过校验后写入。硬件和裁剪参数需停止采集后修改。显示、滤波、共享开关/范围/降采样可在线应用；修改独立存储路径、格式、分段或压缩前先关闭 SAVE，DAS 采集可以继续。左右参数区宽度可拖动，与 View 参数区联动。

主区摘要按行显示 Scan、Fiber Length、dx、GL、PolarDiv、Detrend/绘图滤波、crop：

- Fiber Length = Points × 0.4 m。
- dx = 0.4 × Merge m，表示合并后空间步长。
- GL = 0.4 × Merge × DiffOrder m。
- PolarDiv 绿/红表示该配置启用/关闭，不是硬件健康状态。
- 裁剪参数使用 `[CropStart, CropEnd)`，CropEnd=0 表示取到末尾。摘要显示实际保留的包含端点范围 `crop: CH a~CH b (Total: nCH, 距离)`，距离为 n × dx。

### 5.2 三个参数窗口的内容

| 小页 | 参数与使用方法 |
| --- | --- |
| 采集窗口 / 基础采集 | Scan 为每秒扫描次数；Pulse 为脉冲宽度 ns；Points 为每次扫描点数，修改后旁边预览 Fiber Length。Channels 设置上传通道数，Source 选择采集卡上传类型。共享模式要求单通道 PHASE。 |
| 采集窗口 / 硬件设置 | 设置内部/外部时钟、触发方向、Bypass 跳过点数、中心频率 MHz、DataRate、Rate2Phase 和 PolarDiv。按实际接线与采集卡配置设置，不能用显示参数替代硬件参数。 |
| 采集窗口 / 相位处理 | SpaceAvg 为空间平均；Merge 为空间合并，旁边预览 dx；DiffOrder 决定空间差分间距，旁边预览 GL；Detrend 设置去趋势带宽；CropStart/CropEnd 控制处理后保留范围；两个输入框后实时显示“原有 n CH → 裁剪后 m CH”，原有通道数指空间合并后、裁剪前的通道数。 |
| 时长设置（按用途分到三个窗口） | Length/Load 为每次 DLL 读取块时长；Length/Plot 为显示窗口时长；Length/Save 为保存包时长；Length/File 为单文件分段时长；Length/Comm 为共享周期。时长会换算为整数扫描帧，按界面提示满足块长和倍数约束。共享启用时 Comm 必须等于 FIP 包时长。 |
| 独立存储窗口 | 设置路径、BIN/BZ、Save DS、满盘覆盖最旧文件、Zstd 级别、Bitshuffle 块长度和 BZ 压缩线程数。Save DS 越大保存的时间采样越稀疏；覆盖开关涉及旧数据删除，启用前确认目录。 |
| 共享与显示窗口 / 绘图显示 | 设置波形 Region、相位 rad 显示、显示滤波/频段、时空图空间范围、窗口块数、时间/空间显示降采样、色标上下限、配色，以及纵轴单位和 x0。仅改坐标单位不会改变落盘数据。 |
| 共享与显示窗口 / 数据共享 | 设置共享开关、CH 起止（终点包含）、时间和空间降采样。共享会影响 View 和联合保存的 DAS 范围/采样率，不改变独立 DAS 原始保存范围。 |

### 5.3 波形、PSD 和时空图

- **Phase / RAW / Monitor**：选择相位、原始数据或监视通道。Phase↔RAW 会改变硬件上传方式，必须停止后切换；RAW 不支持 4 上传通道。Phase↔Monitor 可在线切换。
- **显示 PSD**：勾选显示频谱；取消后时空图自动增高填满空余区域。
- **TIME / SPACE**：沿用原 PCIe 上位机语义。TIME 显示一帧沿光纤的空间波形；SPACE 显示指定 CH 随时间变化的波形。SPACE/Monitor 与时空图时间轴联动；TIME/RAW 的横轴含义不同，不建立该时间联动。
- **CH**：SPACE/Monitor 下选择通道，从裁剪后的首个通道 0 开始。应在有效裁剪范围内选择。
- **时空图纵轴**：在采集参数窗口选择 Points、Distance (m) 或 Distance (km)。距离为点号×dx+x0；km 模式中 dx 先换算为 km。x0 使用当前选定单位，默认 0；改单位时应同时核对 x0。

波形、PSD、时空图保持绘图区宽度一致。图形默认 Times New Roman 12 pt；通过 Setting 全局入口统一调整。

## 6. Tab3：FIP 通信、对齐和 FIP 独立存储

### 6.1 通信设置和按钮

设置监听 IP、端口、FIP 包时长、每传感器采样率和传感器数量，然后点击 **FIP 通信按钮**启动服务。默认监听地址 `0.0.0.0:3677`，表示本机所有网卡；发送端应连接运行本软件电脑的实际 IP，而不是把 `0.0.0.0` 当作目标地址。监听启动成功后等待发送端连接；防火墙需允许对应 TCP 端口。

包时长和采样率必须与发送端一致；采样率字段使用 MHz，例如 1 MHz 填写 1。单/双传感器配置必须与发送端数据排列一致。统计区显示连接、收包、缺包、速率、通信序号和对齐状态。清除统计用于重置界面统计，不会修复发送端数据或补回缺包。

该页没有 eDAS TCP 启用按钮。eDAS 状态来自本机采集与共享，独立启停请到 Tab2；联合启停请到 Tab1。

### 6.2 FIP TCP 协议

接收实现位于 `src/fip/tcp_server.py`，协议如下：

| 字段 | 字节与编码 |
| --- | --- |
| 包头前 4 字节 | `comm_count`，大端无符号 32 位整数。 |
| 包头后 4 字节 | `data_length`，大端无符号 32 位整数，表示随后的数据体字节数。 |
| 数据体 | 大端有符号 64 位 Q40.24 定点数序列；字节数应为 8 的倍数，解码为 float64，数值 = int64 / 2^24。 |
| 双传感器排列 | 逐采样交织：FIP1[0]、FIP2[0]、FIP1[1]、FIP2[1]……；单传感器直接使用整个序列。 |

TCP 为字节流，接收端按包头/包体长度读取，支持分次到达。非法长度会关闭当前连接并等待重连以恢复字节边界。原始通信序号保留用于诊断，会话内归一化序号用于处理/对齐；序号跳跃记入缺包统计。解码值的物理含义以 FIP 设备标定为准。

### 6.3 本页存储和配置控制

- **FIP 独立存储**：启用后按路径、保存间隔和 FIP 降采样写入 NPZ。单传感器保存一路，双传感器保存拆分后的两路；文件为保存链路数据，不等于 View 当前经过显示滤波的曲线。
- **存储日志/统计**：查看 FIP、eDAS、联合数据的完成/失败、最近文件与写入信息。联合开关和参数入口已迁至 View。
- **保存配置 / 加载配置 / 重置配置**：管理 GUI 配置。运行前保存，加载或重置前停止两路；跨机器携带完整传感参数推荐使用 Setting 的 `.par` 导出/导入。

## 7. Tab4：Setting、配置恢复与参数包

**应用并保存全局设置**保存 GUI 字号、所有图刻度与标签字号、PSD 降采样等。默认 GUI 参数文字 10 pt、按钮 12 pt、图形文字 Times New Roman 12 pt。图形字号统一作用于 View 和 eDAS，含时域、PSD、时空图。可选检测页默认隐藏，按需要启用；检测页保留特征计算、阈值、触发前后存储和报警历史功能。

**导出参数**选择 `.par` 文件，导出当前完整 FIP/eDAS、绘图、共享、存储和全局配置，不含传感数据、运行计数或采集状态。**导入参数**需要停止两路且没有等待启动任务；软件先验证封装、认证和参数类型/范围/周期一致性，通过后应用并保存，下次启动继续使用。导入不启动采集或通信。

`.par` 使用带版本头的二进制封装、压缩 JSON、随机 nonce 和 AES-256-GCM 加密认证，普通文本编辑器无法直接读取参数，篡改会被拒绝。程序使用内置便携密钥，便于相同软件跨机器导入；这是一种非明文封装和完整性保护，不是用户密码访问控制，也不承诺抵抗源码分析。依赖 `cryptography`，安装见 requirements。

默认 GUI 快照为 `config/gui_last_state.json`，包含完整 eDAS 参数。旧 `config/edas_last_params.json` 用于兼容恢复；eDAS 参数保存会同步统一快照。参数窗口中未点击“应用并保存”的草稿不属于默认配置。启动快照异常时检查日志，并重新保存有效参数。

## 8. 联合存储与高速写入

### 8.1 入口和参数

在 View 点击 **存储参数设置…**，设置联合保存开关、保存路径、分段间隔、FIP 保存降采样、缓存时长、文件格式和 H5 压缩。应用并保存后生效。采集/通信运行中仅允许切换联合保存开关；要修改路径、格式、分段或数据形状参数，先停止两路。

联合保存需要 FIP 数据与 eDAS 共享数据进入对齐链路。请启用单上传通道 PHASE 共享，并使共享周期与 FIP 包时长一致。只启动单路时可以独立保存，不能形成完整双路联合包。共享关闭后独立 DAS 仍可保存。

### 8.2 格式与数据精度

| 保存入口/格式 | 数据与用途 |
| --- | --- |
| eDAS 独立 BIN | 原始 int32 计数，按 Save DS 保存；适合优先降低 CPU 压缩开销。 |
| eDAS 独立 BZ | 原始 int32，经 Bitshuffle + Zstd 压缩；吞吐取决于数据可压缩性、CPU 与线程设置。 |
| FIP 独立 NPZ | 未压缩 NPZ，保存 FIP 保存链路数据和元数据；双传感器按两路组织。 |
| 联合 bin32（默认） | 魔数 `FIPeDAS2`；FIP float64、DAS float32 弧度，兼顾容量与吞吐。float32 约 7 位有效数字。 |
| 联合 bin | 旧魔数 `FIPeDAS1`，DAS 使用 float64；同等 DAS 数据所需空间约为 int32 的两倍。 |
| 联合 npz | 快速无压缩 NPZ，保留原字段与精度，现有 fipedasREAD 可读；文件较大，避免高吞吐时 ZIP 压缩积压。历史压缩 NPZ 仍可读取。 |
| 联合 h5 | HDF5 可选压缩；压缩会增加 CPU 开销。需可用的 h5py；缺少依赖时实现会回退到 BIN，应检查日志和实际文件。 |

需要完整原始计数时启用独立 DAS 保存，不能用共享后 float32 联合数据替代。根目录 `fipedasREAD` **源码**支持 bin32；历史 `dist` EXE 未重打包，不支持新格式，上传时也排除该目录。

### 8.3 排空、错误与性能边界

采集、共享和保存通过有界队列分离。停止时排空队列及文件尾部；不要在“正在停止/排空”时强制结束进程。DAS 完成文件在 flush/fsync/close 成功且包含数据后计数；FIP 完成数只统计成功写入；联合 BIN/bin32 通过临时 `.part`、刷新和重命名发布完成文件。

队列溢出、内存字节预算或磁盘错误会报告故障；部分链路会停止采集以避免继续扩大丢失。故障会话不能当作完整无损采集，需检查日志、剩余空间、磁盘持续写速及存储参数。

此前 E 盘 10 秒合成实盘测试：600 MB/s 输入下独立/联合同时保存无丢块，bin32 停止排空约 47 ms。该结果仅覆盖当次短时合成测试，不代表真实采集卡、BZ/H5 压缩或长时间持续运行均达到相同能力。现场应使用目标磁盘和实际格式复测，预留文件系统、SSD 缓存耗尽与后台任务带来的吞吐余量。

### 8.4 联合存储相关报错、弹窗和提示

#### 会单独弹窗的情况

| 弹窗标题 | 提示内容 | 条件与处理 |
| --- | --- | --- |

| `Tab3 Warning` | `联合尾部保存失败：联合尾部写入超时；缓存仍保留；请保留日志并检查磁盘` | 停止时提交尾部后没有在截止时间内完成。前后阶段共用约 60 s 的截止时间，不是各等待 60 s。 |

#### 在“存储参数设置…”窗口内显示，不另弹窗

点击“应用并保存”时校验失败，会保留参数窗口并在其中显示错误，拒绝本次应用：

| 提示内容 | 触发条件 |
| --- | --- |
| `启用联合存储时必须设置存储目录。` | 启用联合保存但目录为空。 |
| `存储目录不能是已有文件。` | 目录字段实际指向一个文件。 |
| `存储目录格式无效或无法访问。` | 路径检查发生异常。这项检查不等于实际写盘权限或可用容量测试。 |
| `请先停止采集和 FIP 通信，再修改存储路径、格式和分段参数。` | 运行中尝试修改受保护参数；正常界面已将这些参数禁用，此处是额外校验。 |

#### 不会立即弹窗的运行期异常或等待状态

| 提示/日志 | 当前行为 |
| --- | --- |
| `联合存储未写入数据超过2 GiB；磁盘或FIP对齐落后，停止采集` | 触发链路故障，停止 eDAS，更新状态并记录日志；停止排空失败时可能再弹出尾部保存失败。 |
| `error: joint FIP+eDAS request too large (...)` / `TAB3_NODE storage.joint_too_large` | 单请求超限，更新存储状态和失败计数，返回写盘失败，不推进游标，不立即弹窗。BIN/bin32 与 NPZ/H5 的阈值不同。 |
| `DAS storage _save failed: {具体异常}` | 创建目录、打开/写入文件、数据序列化、flush/fsync、文件重命名等任一操作抛出异常。后台记录含堆栈的错误、返回失败，并将异常类型和内容发送到存储状态区；停止时的尾部失败弹窗也附带最近的具体原因（2026-10-23 更新）。 |
| `DAS storage worker error: ...` | 写盘线程外层执行异常，记录日志并返回请求失败。 |
| `lossless backpressure` / `joint_slow` | 存储队列施加背压，或一次写入耗时较长；记录警告，不立即弹窗。 |
| `h5py is not installed ... falling back ... bin` | H5 依赖缺失，回退为 BIN，并记录警告。此项本身不代表保存失败。 |
| `Waiting complete FIP/eDAS pair ...` / `Collecting joint chunk ...` | 等待完整配对或收集到分段时长，属于状态提示。 |
| `联合存储等待FIP；DAS独立存储请在eDAS页启用` | 当前缺少 FIP，不能按完整双路联合包保存。 |
| `采集停止：共享尾部 ... 帧不足一个对齐周期，未写入联合文件；原始尾部仅在启用DAS独立存储时保存` | 共享不足一个周期的尾部提示，不是“联合尾部写盘失败”。 |

若同时启用 Tab2 的 **DAS 独立保存**，还可能看到标题 `Storage Error`、正文 `Failed to start data saving: ...` 的弹窗。它属于独立 DAS 保存启动失败，应与联合写盘区分。FIP 的“通信错误”、采集卡初始化及采集启动错误也可能阻断联合运行，但不属于联合文件写入失败。

### 8.5 “联合尾部写盘失败，游标未推进”的原因与排查

这句话不是底层异常本身。`EDASManager._flush_joint_on_stop()` 提交尾部保存请求，等待请求完成后检查成功保存位置 `_last_snapshot_end_comm`；若仍小于本批末尾序号 `request.end_comm`，就生成这条提示。写盘成功才推进该位置，避免把失败数据误标为已保存。**“游标未推进”是写入未确认成功的结果，不是需要手动修复的磁盘指针。**

在当前正常的请求回调流程下，常见来源分为两类：

1. **写盘请求被大小限制拒绝。** NPZ/H5 使用约 2 GiB 的单请求估算阈值，BIN/bin32 使用 64 GiB 阈值。此处估算累计的是请求内数组，并非最终文件精确大小或实际独立内存占用。日志会包含 `joint_too_large`。可在停止后减小分段时长、减少共享通道/提高共享降采样，或核对是否应使用 bin32。缓存字节预算与单请求阈值是不同检查。
2. **实际保存抛出异常。** 例如目标路径不存在且无法创建、路径实际是文件、权限不足、磁盘空间不足、外接盘/网络盘掉线、写入或刷新失败、临时文件重命名被拒绝，或格式序列化/数据形状/内存分配异常。日志会包含 `DAS storage _save failed: ...`；应依据后面的具体异常诊断，不能一概归为磁盘硬件故障。

2026-10-22 版本中，写盘线程只把原始异常记到日志并返回成功/失败，因此可能先看到概括弹窗。2026-10-23 起，存储状态会显示具体异常类型/内容，停止时的尾部弹窗也附带“原因：...”并保留完整日志堆栈。运行中失败仍不推进成功游标，以便重新收集。

**2026-10-22 现场反馈：** 另一台电脑测试时出现本条提示，当次日志未带回。本地可访问日志仅到 2026-10-21 22:54，未发现对应联合错误，故目前不能确认该次具体底层原因，也不能认定是磁盘故障。本地小数据诊断中，BIN/bin32/NPZ/H5 的完整配对、仅 FIP、仅 DAS、混合缺路尾部及双 FIP 缺一路数组场景均可保存；该结果不覆盖现场设备、配置、真实吞吐和磁盘环境。

再次复现时建议：

1. 记下操作顺序（开始/停止/退出/单路切换联合）、发生时间、联合格式、路径、分段时长、共享通道和降采样。
2. 拷贝该次 `version_inDAS/logs/pccp_monitor_*.log`，保留弹窗之前的记录。搜索 `DAS storage _save failed`、`storage.joint_too_large`、`DAS storage worker error`、`Joint storage tail was NOT fully persisted` 和 `joint_storage failed`。
3. 核对目标盘剩余空间、写权限、是否为网络/移动盘，以及保存目录中是否遗留 `.bin.part`。保留未完成文件用于诊断，不把它直接改名当成完整文件；没有 `.part` 也不能排除写盘失败。
4. 用本地可写目录、bin32、较短分段和较少共享通道做对照。对照成功只能帮助缩小路径/格式/吞吐/数据量因素，不能替代原始异常日志。

错误主要影响当次尚未确认保存的尾部或失败批次，不意味着此前所有完成文件都已损坏；应分别核对完成文件与日志，不能把该会话当作已证明完整无丢失。

### 9.3 联合文件快速查看

根目录 `fipedasREAD` 的当前源码支持联合 BIN v1、bin32 v2、NPZ、H5。运行：

```powershell
python ../fipedasREAD/run.py D:/PCCP/FIPeDASDATA
```

BIN/bin32 现使用只读内存映射，只索引包结构，按所选曲线和时空图访问数据；时空图在转换/拼接前进行像素预算降采样，默认约 30 万像素。截断或非法长度会明确报错，连续操作时丢弃尚未执行的过期重绘请求；文件缓存同时检查大小和修改时间。映射打开期间请勿改写、删除或替换正在查看的文件。

本机 132,000,727 字节、2 帧、每帧 64×250000 的 bin32 合成对照，热缓存下整文件复制约 69.7 ms、RSS 增量约 132 MB；映射索引约 0.86 ms，随后生成 299136 像素预览约 26.2 ms。索引耗时不包含访问全部数据页，不等于冷盘完整读取耗时。NPZ 压缩和 H5 当前不使用这套 BIN 内存映射路径。

旧的回放 EXE 不会自动获得源码更新。需使用本次重新打包的回放程序，或执行 `python ../fipedasREAD/build_exe.py` 重新生成；回放 `dist/` 继续排除上传。

### 9.7 1 s 分段、慢写盘与 Stop 排空

10:52:58 测试日志中，联合 NPZ 保存 1 s 大块耗时约 6.3～8.1 s；eDAS 10:53:18 已停采，但尾部排空直到 10:54:42 才完成。慢压缩造成积压，旧尾部还会继续追赶新到的 FIP 数据，并在处理事件时重入 Stop。现已改为联合 NPZ 无压缩快速归档，正常/积压/停止尾部均按设置时长分文件，结合字节和通道边界提前分段；单个通信帧不拆开，所以分段精度不小于通信周期。1 s 文件表示覆盖 1 s 采样数据，不是磁盘在任何负载下都保证每墙钟秒完成一文件。

### 9.8 源码/EXE 闪退诊断

正常使用 `python run.py` 启动，程序会在导入 Qt 和采集卡代码之前建立 `logs/crash_reports/crash_日期_时间_PID.log`。文件包含 Python 位数/版本/路径、未处理异常堆栈、可捕获的 native fatal 线程栈及 Qt 警告；普通日志每 10 s 同时记录 `PROCESS_MEMORY`。Python 回调异常会请求停止采集并显示错误状态，避免只在消失的控制台中留错。

正常清理记录 `APPLICATION_CLEANUP_COMPLETED`，解释器退出记录 `PYTHON_ATEXIT`；缺少标记说明未完成相应阶段，但不能单凭标记缺失判断具体故障。操作系统强杀、断电或严重底层损坏未必能写出栈。若再次闪退，请保留同次运行的普通日志和 crash_reports 文件；另保留 Windows“应用程序错误”的故障模块/异常代码。不要把“缓存按预算裁剪”提示等同于内存耗尽。
