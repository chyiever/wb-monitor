# 数据存储说明：BIN / BIN32、数据来源与原始性

适用软件：`version_inDAS` 内置 eDAS 版本，dev2。核对日期：2026-10-23。本文依据当前源码；历史 EXE 或外置 `version_exDAS` 的行为不能直接套用。

## 1. 先回答两个问题

**新版 BIN（界面名称 bin6432）保存 DAS 原始 int32 相位整数、FIP float64，后缀为 `.bin6432`。BIN32 继续保存 DAS float32 弧度、FIP float64，后缀为 `.bin`。** 两者都不压缩，不经过 GUI 显示滤波；通道选择和共享降采样仍生效。

**当前联合文件保存的是未经过 GUI 显示滤波的相位数据，不是未经任何处理的 ADC 原始数据或网络原始字节。** DAS 来自采集卡输出的 PHASE，经软件裁剪、共享范围选择及可选共享降采样；新版 BIN 直接保留整数，不做弧度换算，BIN32/NPZ/H5 沿用弧度路径。FIP 来自 LabVIEW TCP 数据的定点解码、按传感器拆分和可选联合存储降采样。

“原始”必须说明相对于哪一级：设备 ADC、设备相位输出、本软件接收值、共享流、显示结果是不同层级。文件或代码中出现 `raw`、`unwrapped_data`，不能单凭名称判断实际处理过程。

## 2. 三个存储入口

| 入口 | 保存内容 | 格式 | 与其他入口的关系 |
| --- | --- | --- | --- |
| Tab1 → 存储参数设置 → 联合存储 | 按 comm 序号配对的 FIP + DAS 相位数据 | BIN、BIN32、NPZ、H5 | DAS 来自共享流；要求两路完整配对，不是屏幕曲线导出 |
| Tab2 → DAS 独立存储 | 采集线程交出的完整数据块，再按 Save DS 选择空间点 | 独立 BIN、BZ | 不经过共享范围/共享降采样和显示滤波；PHASE 已按采集裁剪设置裁剪 |
| Tab3 → FIP 独立存储 | 接收到的 FIP 相位，经异常值检查和独立存储时间降采样 | NPZ | 不经过显示滤波或显示相位展开；降采样与联合 FIP 存储分别设置 |

独立 DAS BIN 与联合 BIN 是不同文件格式，不能因为扩展名相同就用同一裸数组读取方法。内置版 Tab2 使用 `edas_hardware` 的独立保存器；旧 DAS TCP 管线中的独立保存类不等于当前 Tab2 保存入口。

## 3. Tab1 BIN 与 BIN32 的具体区别

| 项目 | BIN | BIN32 |
| --- | --- | --- |
| 文件扩展名 | `.bin6432` | `.bin` |
| 文件头魔数（前 8 字节） | `FIPeDAS3` | `FIPeDAS2` |
| format_version | `wb-monitor-joint-bin-v3` | `wb-monitor-joint-bin-v2` |
| DAS 类型 | 小端 int32，4 字节/样本，相位整数 | 小端 float32，4 字节/样本，弧度 |
| FIP 类型 | 小端 float64，8 字节/样本 | 小端 float64，8 字节/样本 |
| 数据压缩 | 无 | 无 |
| 帧、序号与采样率等结构 | JSON 文件头 + 逐帧记录 | 同类结构，通过魔数识别 DAS 位宽 |
| 当前内置共享流的精度 | 精确保留被选中的 int32 整数 | 整数转 float32 弧度，存在浮点舍入 |

共享器独立保留选取后的 int32 整数矩阵，同时为在线绘图与旧浮点格式生成弧度矩阵。新版 BIN 写盘使用整数矩阵，**禁止从已经舍入的弧度值反算整数**；整数源缺失时明确保存失败，不静默转换。文件头记录 `das_dtype=<i4`、`fip_dtype=<f8`、`das_units=phase_integer`、`das_scale_to_rad=π/32767`；换算系数仅供读取者需要时使用，落盘数据仍是整数。

历史 BIN v1（`FIPeDAS1`、`.bin`）保存 DAS float64 弧度，读取器继续兼容。新写入使用 v3 和新扩展名，不能把历史浮点文件改后缀当作整数文件。

忽略文件头开销，设一个文件中 DAS 值总数为 D、FIP 值总数为 F：

- 新版 BIN6432 数据体约为 `4D + 8F` 字节。
- BIN32 数据体约为 `4D + 8F` 字节。
- 两种当前格式的数据体大小相同；旧 BIN v1 为 `8D + 8F` 字节。

例如 DAS 600 通道 × 100000 Hz × 1 s，FIP 两路 × 1000000 Hz × 1 s，无降采样：BIN6432 和 BIN32 数据体均约 256 MB，旧 BIN v1 约 496 MB（十进制 MB，不含头部）。这只是按样本数量计算的体积，不是实际磁盘吞吐测试结果。

需要保留相位整数时选择 **bin6432**；需要弧度浮点文件时可继续选择 BIN32。旧读取器不认识新 v3，必须更新 fipedasREAD 源码；更改扩展名不能实现格式转换。内部配置键仍为 `bin`，原先选中 BIN 的配置升级后写新版 `.bin6432`；默认 BIN32 配置不会被自动替换。

## 4. DAS 究竟经过哪些处理

### 4.1 设备处理与软件处理的边界

程序通过 DLL 的 `set_phase_dem_param` 下发 Rate2Phase、SpaceAvg、Merge、DiffOrder、Detrend 带宽及 PolarDiv。这些属于设备/驱动的相位处理配置。保存 PHASE 时，保存的是这些配置下设备提供的相位输出，不能称为未经相位处理的 ADC 电压数据。设备内部的具体实现和频率响应需查硬件/DLL 文档，不能仅凭本软件源码确定。

采集线程读取 PHASE 整数块后先执行软件空间裁剪，再把完整块分给独立存储、共享及显示三个消费者。显示消费者的时间滤波发生在分流之后。

```text
采集卡 / DLL 的 PHASE 输出（受硬件相位参数影响）
    → 软件空间裁剪
        ├→ Tab2 独立存储 → Save DS 空间抽点 → BIN / BZ
        ├→ 共享 → CH 范围 / 空间抽点 / 时间抽点
        │         ├→ int32 整数 → comm 对齐 → BIN6432
        │         └→ float32 弧度 → BIN32 / NPZ / H5、Tab1 显示滤波与绘图
        └→ Tab2 显示滤波、显示降采样与绘图
```

### 4.2 联合文件里的 DAS

1. 已受设备相位处理参数影响，也已执行软件 Crop。
2. 应用 Tab2「数据共享」中的 CH 范围、空间降采样和时间降采样。
3. 新版 BIN6432 保留 int32 整数；BIN32/NPZ/H5 将相位换算为 float32 弧度：`phase_rad = phase_integer × π / 32767`。
4. 按 comm 序号配对后写盘；不使用 Tab1/Tab2 的显示滤波输出，也不使用时空图去基线后的矩阵。

因此这是“**未经过显示滤波、已选通道/可选降采样的设备相位数据**”。共享降采样、范围选择和裁剪丢弃的样本，不能从联合文件恢复。共享时间降采样直接抽点，没有在共享器中自动增加抗混叠滤波；如需完整频带留档，应保留足够采样率，必要时令共享时间降采样为 1。

### 4.3 独立文件里的 DAS

Tab2 BIN/BZ 的 PHASE 数据以 int32 保存，保留该保存路径上的整数值，不经过联合流的弧度换算。Save DS 是**空间抽点**，不是降低 Scan 时间采样率：`每帧空间数据[::SaveDS]`。Save DS=1 保留裁剪后全部空间点；大于 1 则减少空间点数。BZ 的 Bitshuffle + Zstd 是无损编码压缩，不等于信号滤波。

PHASE 独立保存仍是设备处理后、软件裁剪后的相位值。选择 RAW 上传模式可以独立采集保存 RAW 来源数据，但与 PHASE 的含义、布局不同；当前联合共享只支持单上传通道 PHASE，不能把 RAW 独立文件当作联合 PHASE 文件解释。独立保存器统一写 int32，读取时应按对应格式、数据源及保存参数解码。

## 5. FIP 究竟经过哪些处理

### 5.1 本软件接收到什么

TCP 服务从 LabVIEW 客户端接收大端有符号 64 位 Q40.24 定点样本，解码为 `float64(整数) / 2^24`。多传感器数据按采样点交织布局拆分。这里的值是发送端交付的工程相位值；LabVIEW 或 FIP 硬件在发送前做了什么处理，不能从本仓库确定。因此本软件中的“接收原始相位”不等于 FIP ADC 原始数据，也不是 TCP 原始字节备份。

### 5.2 联合存储里的 FIP

- 联合管理器直接接收原始接收包，拆分后交给对齐器。
- **不使用显示滤波结果，不执行显示相位展开，也不执行 FIP 独立存储的异常极值修复。**
- 联合存储 FIP 降采样为 K 时，每个传感器写 `data[::K]`，有效采样率记录为接收采样率/K；这是时间抽点，没有自动抗混叠滤波。
- BIN6432 与 BIN32 的 FIP 均写 float64。K=1 且包解析/拆分正常时，保存该接收包解码后的各路相位样本；不承诺逐字节还原原 TCP 报文。

代码/历史 NPZ 字段沿用 `unwrapped_data`、`unwrapped_by_sensor` 等名称，但当前联合入口填入的是接收相位，不是在此处执行了 unwrap。判断应以入口代码为准。

### 5.3 独立存储里的 FIP

独立 FIP 保存沿独立原始包路径，**不经过显示滤波或显示相位展开**，但保存前调用异常值检查：非有限值或绝对值大于 `1e6` 的样本按有效邻点线性插值修复；两端使用最近有效值，整段无有效值时置零。随后执行独立存储时间抽点，并用 float64 保存到 NPZ。

因此正常样本、降采样=1 且未触发修复时，独立文件与接收解码值一致；出现异常值时它不是严格未经修改的数据备份。文件标记 `phase_unwrap_enabled=False`、`phase_raw_downsampled`；这些标记不代表从未进行异常修复。同一时段的独立 FIP 与联合 FIP 若不完全一致，应先比较两种存储的抽点因子、时间覆盖范围和异常值修复日志。

## 6. 哪些界面参数会影响文件

| 设置 | 联合 DAS | 联合 FIP | 独立 DAS | 独立 FIP |
| --- | --- | --- | --- | --- |
| Tab1 波形滤波、FIP 显示 unwrap | 不影响 | 不影响 | 不影响 | 不影响 |
| Tab2 显示滤波（两页时空图共用） | 不影响 | 不影响 | 不影响 | 不影响 |
| 绘图显示降采样、去基线、配色、纵轴单位、隐藏时空图/PSD | 不影响 | 不影响 | 不影响 | 不影响 |
| 设备相位处理配置、PHASE Crop | 影响 | 不影响 | 影响 PHASE | 不影响 |
| 共享范围、共享时间/空间降采样 | 影响 | 不影响 | 不影响 | 不影响 |
| Tab2 Save DS | 不影响 | 不影响 | 影响空间点数 | 不影响 |
| 联合 FIP 存储降采样 | 不影响 | 影响时间点数 | 不影响 | 不影响 |
| 独立 FIP 存储降采样 | 不影响 | 不影响 | 不影响 | 影响时间点数 |
| BIN6432 / BIN32 格式选择 | int32 相位整数 / float32 弧度 | 不改变 FIP 位宽 | 不影响 | 不影响 |

“绘图显示降采样”和“数据共享降采样”是不同入口，前者只影响屏幕，后者影响联合文件。分文件时长改变文件分段，不应被理解为采样率或滤波设置。

## 7. 文件格式、读取与完整性

联合存储文件名中的秒保留三位小数（毫秒），例如 `FIPeDAS-20261023-123456.789.bin6432`；BIN6432、BIN32、NPZ、H5 共用这一命名规则。同一毫秒内如已有同名文件或对应 `.part` 临时文件，追加 `-1`、`-2` 等序号避免覆盖。此规则只影响文件名，不降低文件内部时间字段的数值精度。

- 联合 BIN6432/BIN32：魔数 + JSON 元数据 + 逐帧记录，DAS 为通道×时间矩阵；逐帧有 comm、时间、采样率、形状与两路存在标记。文件头记录共享后的 DAS channel_start/channel_step 及相应单位。
- 联合 NPZ：当前为无压缩 NumPy 归档，保留逐帧数组及元数据；不是旧版耗时较高的压缩写盘。容器中的对象数组需要相应读取器，勿对不可信文件随意启用 pickle。
- 联合 H5：分传感器 FIP 数据集及 DAS 数据集，可选 gzip。压缩是无损编码，不是信号滤波。当前 H5 的 DAS 容器使用 float64，同样不能增加当前 float32 共享源的真实精度。缺少 h5py 时程序会记录警告并回退 BIN，应检查实际文件及日志。
- 本仓库 `fipedasREAD` v1.2.1 当前源码可读联合 BIN v1、BIN32 v2、新 BIN6432 v3、NPZ、H5；BIN 系列使用只读内存映射和索引。v3 的底层 `das_frames` 保留 int32，**绘图前**按文件头 `das_scale_to_rad`（当前为 `π/32767`）换算 rad；DAS 时域曲线在预处理前换算，时空图在选取显示片段后、去基线/预处理前换算，避免整文件浮点展开。未归一化时坐标/色标为 rad，归一化后无量纲；文件和底层整数数组不改写，历史弧度文件不重复换算。当前整数与历史弧度文件仍不支持混合拼接。长曲线的时间戳随自动预处理抽点和手动降采样同步选取，保持原始时间覆盖及文件间隙。旧 dist EXE 未包含这些更新，需从源码运行或重新打包。
- 新版 BIN6432 先写 `.bin6432.part`，flush/fsync 成功后改名为 `.bin6432`；BIN32 对应 `.bin.part` → `.bin`。联合游标只在写盘成功后推进。残留 `.part` 不是已成功完成的文件，不应直接改扩展名视为完整数据。这项原子完成策略不能泛化到所有独立保存格式。
- 正常联合保存等待连续完整的两路配对。停止时不足一个共享周期的 DAS 尾部不能组成完整联合包；仅在启用独立 DAS 保存时可由独立路径保留。总文件数不能直接代表样本完整性。

建议检查文件元数据的有效采样率、通道数、comm 连续性、时间覆盖和日志中的 dropped/gap/写盘错误。`1 s/文件` 是采集时间分段目标，不等于磁盘必须每个墙钟秒立即出现一个完整文件；队列、停止排空及边界切分会影响完成时刻和尾文件长度。

## 8. 留档建议与源码依据

若希望尽量保留设备输出相位：启用独立 DAS 保存、Save DS=1，按需要设置 Crop；联合共享及两种 FIP 保存的降采样设为 1，并核实共享范围。保存同次运行的 `.par` 参数文件、日志、软件提交版本和设备配置。联合文件元数据包含基本形状/时间信息，**不包含所有设备处理与滤波设置的完整快照**，单独保留 `.par` 有助于复现。
