# Tab1 波形与时空图刷新延时分析

依据现场日志：`pccp_monitor_2026-10-23_12-25-22.log`。分析与修改日期：2026-10-23，适用 version_inDAS/dev2。

## 1. 日志证据

日志共 1461 行，未记录 ERROR，正常 Stop 和 cleanup。停止统计显示：

| 环节 | 记录 |
| --- | --- |
| eDAS 绘图 | 入队 240 包，处理 228 包，丢弃 12 个绘图队列包，228 包均达到 slow 阈值 |
| 绘图每包耗时 | 最小 608.30 ms，中位数 824.17 ms，平均 895.08 ms，最大 2174.85 ms |
| 等待同段提示 | `VIEW_WAIT_PAIR` 共 41 次；日志有 5 s 限频，不等于只等待了 41 次 |
| 联合存储 | 入队/保存均为 240 请求，丢弃 0，失败 0 |
| 联合写盘耗时 | 中位数 176.39 ms，平均 197.29 ms，最大 1108.29 ms |
| 独立 FIP 保存 | 120 文件，每文件 2 s；统计每传感器保存样本数 240000000 |
| FIP 处理 | 240 包全部处理，队列丢弃 0、处理失败 0、gap_count=0 |

绘图丢弃发生在独立显示队列，不能解释为联合存储丢数。本次联合请求全部报告成功，日志没有显示对应的存储丢弃；但仅靠这些统计不能证明设备、驱动、发送端和磁盘文件全链路逐样本完整。

采集快照显示测得帧率接近配置 100000 Hz，部分循环 0.7～0.8 s、驱动缓存有约 0.15～0.45 s 积压。进程私有内存约 4.8 GB，系统可用内存约 119 GB，现有证据不支持认定内存耗尽。两份相位矩阵和较大共享包会增加内存带宽/CPU竞争，但不能从日志量化各自占比。

## 2. 为什么 Tab2 相对流畅、Tab1 却延时

日志中 Tab2 的采集块长为 0.2 s，显示使用空间降采样 2、时间降采样 50；Tab1 共享包长 1 s，DAS 矩阵为 600 通道 × 100000 时间点，最终时空图只有约 600×200 像素。滤波必须先于显示时间降采样，因此处理负载由前面的完整输入决定，不能仅按最终像素数估计。

原实现把 Tab1 两条波形与时空图放在一个 DASPlotWorker 中：先生成曲线，再完整滤波、生成时空图，最后一起发信号。两条曲线即使早已算好，也必须等时空图结束；平均约 0.9 s 的工作耗时叠加 1 s 共享包等待，造成明显延时，遇到超过 1 s 的处理就积压并丢弃旧显示包。

另一个问题是界面只保留各路最新 payload。例如 FIP #10 到达并等待 eDAS #10 时，FIP #11 提前覆盖 #10；随后 eDAS #10 到达，界面只看到 #11/#10，因此明明曾接收完整同序号数据，也无法配对刷新。保留旧画面的逻辑防止了波形跳出 1 s 窗口，却扩大了画面停顿。

## 3. 修复内容

1. Tab1 分为波形工作线程 `curves` 和时空图工作线程 `space_time`，独立有界队列。波形直接发布，不等待时空图滤波；时空图结果不会覆盖波形 payload，也不会推动波形时间轴。
2. GUI 每路保留最多 4 个、有效期 3 s 的显示 payload；当两路最新序号不同，选取缓存中最新且尚未显示的同序号/同周期配对。无完整配对时仍保留上一匹配画面，不拿不同时段的波形强行同步。显示缓存与原始数据存储缓存分离。
3. 时空图保持自己的真实包时间定位，较晚完成的旧图像不会把波形时间轴拉回。两条波形仍按同段数据同步更新；时空图可以稍后独立刷新。
4. 保持两页相同的二阶 Butterworth 因果滤波、时间连续状态和“先滤波再时间降采样”语义。新增通道×时间连续布局的计算入口，减少大矩阵转置/跨步访问；不改变滤波频率响应。断流或通道/采样率改变时清空滤波和图像历史。
5. 两页时空图开关独立，共用 Tab2 滤波参数。关闭 Tab1 时空图后不再向其图像工作线程入队，正在处理的任务可完成；波形、Tab2 显示和数据存储不受该开关影响。Tab2 关闭也不关闭 Tab1。
6. 工作线程日志名称区分 curves/space_time/combined，便于下次现场直接比较两条显示路径的耗时和丢弃统计。
7. 根据追加要求，只有当前显示的页面刷新图形。Tab1 可见时，Tab2 采集线程跳过显示快照、滤波、显示历史拼接与 Monitor 显示读取，停止其显示定时器；Tab2 可见时，Tab1 不再提交波形/时空图计算，清除未处理的显示任务。已开始的计算可完成，不强杀线程。切回页面后从新数据恢复，并重置显示历史/滤波状态，避免补画后台旧数据。硬件采集、FIP 通信、共享、联合/独立保存持续运行，显示开关与参数不因切页而改变。

## 4. 验证与使用边界

本机单次同规模合成对照（600×100000 float32，100 kHz，100 Hz 高通，显示每 500 点取一）：旧计算布局 0.5619 s，新布局 0.4233 s，约 1.33 倍速度，输出一致。该结果不是现场硬件持续运行性能保证，也不意味着时空图不再需要计算时间。

新增测试验证：人为阻塞时空图计算时波形工作线程仍可发布；任一路下一包提前到达后仍能用缓存配对上一包；迟到图像不替换波形；显示缓存有界；Tab1 关闭不入队且两页开关互不影响；跨块滤波结果与原算法一致。

另覆盖页面隐藏后不调用显示变换但完整数据仍分发、真实 Tab 切换时采集线程显示状态/定时器暂停恢复、隐藏 Tab1 不入队。当前页面可能仍需等待下一个完整共享包或采集显示块，切回不代表立即收到一个新的完整包。

最终完整回归 85 项通过（60.670 s），源码控制器启动/清理自检通过。未在本机连接现场采集卡，现场改善幅度仍需用同配置的新日志复核。

当前通信/共享周期仍为现场设置的 1 s，Tab1 获得完整包后刷新，因此本次修复不是亚毫秒连续采样流式显示。若要求每 0.1～0.2 s 都有新波形，应另行设计与 LabVIEW 包结构、序号和存储解耦的增量显示通路，不能仅把 GUI 刷新间隔设得更短。

现场复测建议保留同样采集、滤波、存储参数，对比新日志中 curves 与 space_time 各自的耗时/丢弃数，以及 VIEW_WAIT_PAIR 和采集缓存积压。无需为了显示而修改 BIN6432 的原始整数写盘路径。
