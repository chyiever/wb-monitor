# 2026-07-17 数据存储

## 1. 文档目的

本文档面向开发者，说明当前 `wb-monitor` 版本中 FIP/Tab3 原始数据存储的实现机制、文件格式、线程模型、UI 参数和离线读取方式。文档覆盖三条链路：

1. Tab1 `保存相位数据`：FIP 相位数据独立存储。2026-07-17 更新后支持 1 个或 2 个 FIP 传感器。
2. `FIP+eDAS SAVE`：FIP 与 eDAS 联合存储，沿用原 Tab3 joint storage 设计，以 `comm_count` 对齐两类数据并写入 `.npz`。
3. `eDAS SAVE`：新增 eDAS 独立原始存储，参考 `E:\codes\PCIe-7821\pcie7821_gui\src\data_saver.py` 与 `docs\README-2026-03-20-eDAS数据存储技术说明.md` 的后台队列、分文件、非阻塞入队思路实现。

本次实现还同步调整了 Tab3 左侧参数区布局，以及 DAS Space-Time 图色标策略：默认 `Seismic`，默认 `Vmin=-0.3`、`Vmax=0.3`，后续绘图不再根据数据自动改写手动输入范围。

## 2. Tab3 raw storage UI

Tab3 左侧存储区域标题由 `Joint Raw Storage` 改为 `raw storage`。该区域包含两个可同时开启的保存按钮：

- `FIP+eDAS SAVE`：联合保存 FIP 与 eDAS 数据。
- `eDAS SAVE`：只保存 Tab3 接收到的 eDAS 原始矩阵数据。

两条存储链路互相独立：

- `FIP+eDAS SAVE` 由 `DASStorageWorker` 后台线程写 `.npz`。
- `eDAS SAVE` 由 `EDASRawStorageWorker` 后台线程写 `.bin + .json`。
- 两个按钮可以同时打开。此时 eDAS 每个 TCP 包会进入 eDAS-only 队列，同时达到联合保存条件后，FIP/eDAS 对齐帧会进入 joint 队列。

UI 参数含义如下。为避免左侧参数区出现滚动条，当前布局已经将短标签参数尽量合并到同一行：通信状态、Live Header、Alignment、Curve、Space-Time 与 raw storage 参数均采用紧凑网格；`FIP+eDAS Path` 和 `eDAS Path` 与路径输入框在同一行显示。

| 参数 | 作用 | 当前默认值 |
|---|---|---:|
| `FIP+eDAS Path` | joint `.npz` 输出目录 | `D:/PCCP/FIPeDASDATA` |
| `Joint Length(s)` | 每个 joint chunk 目标时长，达到该时长后入队写盘 | `10.0` |
| `Joint Cache(s)` | 对齐协调器保留的最近数据时长，代码会保证至少大于 joint chunk 时长 | `10.0` |
| `eDAS Path` | eDAS-only `.bin + .json` 输出目录 | `D:/PCCP/eDASDATA` |
| `Blocks/File` | 每个 eDAS-only `.bin` 文件包含多少个 DAS 包/块 | `50` |
| `Cache(packets)` | eDAS-only 保存队列的有效容量，队列满时丢弃最旧包 | `200` |

### 2.1 紧凑 UI 标签与存储模式归属

当前 Tab3 左侧 `raw storage` 区为了避免出现滚动条，会把两套存储参数合并显示在同一组参数行中。因此界面上看到的 `Len(s)`、`JCache`、`Blocks`、`Q` 并不是同一个保存模式的一组参数，而是分别归属于 `FIP+eDAS SAVE` 和 `eDAS SAVE` 两条链路。

| 紧凑 UI 标签 | 完整含义 | 所属按钮/模式 | 配置字段 | 说明 |
|---|---|---|---|---|
| `Len(s)` | Joint Length(s) | `FIP+eDAS SAVE` | `storage.interval_seconds` | 联合存储 joint chunk 的目标时长。达到该时长后，FIP/eDAS 对齐帧会入队写成一个 joint `.npz` 文件 |
| `JCache` | Joint Cache(s) | `FIP+eDAS SAVE` | `storage.cache_seconds` | FIP/eDAS 对齐协调器保留的缓存秒数，用于支持 joint 对齐和增量保存；代码会保证它至少大于 joint chunk 时长 |
| `Blocks` | eDAS Blocks/File | `eDAS SAVE` | `storage.edas_blocks_per_file` | 单个 eDAS-only `.bin` 文件包含多少个完整 DAS 包/block，达到该数量后切到下一个 `.bin` 文件 |
| `Q` | eDAS Queue(packets) | `eDAS SAVE` | `storage.edas_queue_packets` | eDAS-only 写盘队列的有效容量，单位为 packet/block；队列满时丢弃最旧待写包，避免阻塞接收和 UI |

归属关系可以按下面方式理解：

```text
FIP+eDAS SAVE: FIP+eDAS Path + Len(s) + JCache
      eDAS SAVE: eDAS Path + Blocks + Q
```

如果两个按钮同时开启，`Len(s)`/`JCache` 只影响 joint `.npz` 的生成节奏和对齐缓存，`Blocks`/`Q` 只影响 eDAS-only `.bin + .json` 的分文件与队列行为。两条存储链路互不共享写盘队列。

### 2.2 Tab1 FIP 输入参数与单/双传感器模式

Tab1 通信设置区包含 4 个 FIP 输入相关参数：

| UI 参数 | 默认值/可选值 | 作用 |
|---|---|---|
| `单包时长(s)` | `1.000` | 指定一个 FIP TCP 包对应的采集时长，运行时写入 `RawDataPacket.packet_duration_seconds`、`ProcessedData.packet_duration_seconds`、Tab1 `.npz` 元数据和 Tab3 对齐帧 |
| `采样率(MHz)` | `1.000` | 指定传入 FIP 数据的单路原始采样率，运行时换算为 `sample_rate_hz`；默认 `1 MHz` |
| `FIP数量` | `1个` / `2个` | 指定当前 TCP 包中包含 1 路还是 2 路 FIP 传感器数据 |
| `绘图FIP` | `FIP1` / `FIP2` | 仅在 `FIP数量=2个` 时启用，用于选择 Tab1 时域图、PSD 图以及兼容字段 `ProcessedData.downsampled_data` 对应哪一路 FIP |

TCP 包头协议不变，仍是 `comm_count + data_length`。包体仍按 `<32,32>` 定点数解析为 `float64` 相位数组。区别在于 Tab1 会按当前 UI 参数计算每路 FIP 的期望点数：

```text
points_per_sensor = round(采样率(Hz) * 单包时长(s))
payload_points = points_per_sensor * FIP数量
```

默认 `单包时长=1 s`、`采样率=1 MHz` 时：

| 模式 | 默认每包点数 | 包体解释 |
|---|---:|---|
| `1个` | `1,000,000` | 整个 `phase_data` 为 FIP1；软件仍按单 FIP 模式处理和绘图 |
| `2个` | `2,000,000` | 前 `1,000,000` 点为 FIP1，后 `1,000,000` 点为 FIP2 |

如果实际收到的双 FIP 包长度与 UI 配置不一致，但长度可以被 `FIP数量` 整除，程序会记录 warning 并按实际长度均分为 FIP1/FIP2，避免旧采集端参数未同步时直接丢弃整包；后续时间轴、采样率和存储元数据仍以 UI 参数为准。

两传感器模式下，Tab1 处理线程会在同一个 `comm_count` 内同时处理 FIP1/FIP2，并为每个传感器维护独立的相位展开、滤波和降采样状态，避免 FIP1 与 FIP2 的相位连续性互相影响。`ProcessedData` 继续保留旧字段：

- `unwrapped_data`
- `filtered_data`
- `downsampled_data`
- `psd_data`
- `effective_rate`

这些旧字段始终指向 Tab1 `绘图FIP` 当前选择的传感器，用于保持 Tab1 绘图、Tab2 特征计算和旧代码调用方式不变。同时新增按传感器编号索引的字典字段：

- `unwrapped_by_sensor`
- `filtered_by_sensor`
- `downsampled_by_sensor`
- `psd_by_sensor`
- `sensor_count`
- `selected_sensor`
- `packet_duration_seconds`
- `raw_sample_rate_hz`

其中 `packet_duration_seconds` 和 `raw_sample_rate_hz` 来自 Tab1 输入框，用于 Tab2 时间轴、Tab3 FIP 曲线时间轴、FIP/eDAS 对齐帧和 joint 存储元数据。Tab3 使用这些新增字段实现 FIP1/FIP2 独立绘图和 joint 存储。Tab1 选择 `FIP数量=2个` 后，Tab3 `Curve 1`、`Curve 2` 下拉框会从：

```text
Off / DAS Channel / FIP
```

切换为：

```text
Off / DAS Channel / FIP1 / FIP2
```

切回 `1个` 时，Tab3 下拉框恢复为 `FIP`。

### 2.3 Tab1 FIP `.npz` 存储格式

Tab1 `保存相位数据` 仍由 `DataStorageThread` 在后台线程写 `.npz`，主线程只做非阻塞入队。存储链路直接消费 `RawDataPacket`，不依赖 Tab1 绘图处理后的 `ProcessedData`，因此关闭时域图或 PSD 图不会影响保存。

存储线程固定执行：

```text
RawDataPacket.phase_data
  -> 按 FIP数量 拆分 FIP1/FIP2
  -> 每路独立相位展开
  -> 固定 5x 降采样
  -> (输入采样率 / 5) phase_unwrapped_downsampled，默认 200 kHz
  -> 按 存储间隔(s) 分块写 .npz
```

单传感器模式保持旧格式兼容：

- 文件名：`0000001-FIP-<存储采样率>-YYYYMMDDTHHMMSS.mmm.npz`，默认示例为 `0000001-FIP-200K-YYYYMMDDTHHMMSS.mmm.npz`
- `phase_data`：一维数组，长度为当前 chunk 的每路存储样本数
- `format_version`：`wb-monitor-tab1-fip-v1`

双传感器模式新增格式：

- 文件名：`0000001-FIP2-<存储采样率>-YYYYMMDDTHHMMSS.mmm.npz`，默认示例为 `0000001-FIP2-200K-YYYYMMDDTHHMMSS.mmm.npz`
- `phase_data`：二维数组，形状为 `2 x samples_per_sensor`
- `phase_data[0, :]`：FIP1
- `phase_data[1, :]`：FIP2
- `format_version`：`wb-monitor-tab1-fip-v2`

Tab1 FIP `.npz` 字段如下：

| 字段 | 单 FIP | 双 FIP | 说明 |
|---|---|---|---|
| `phase_data` | `float64[samples]` | `float64[2, samples]` | 主数据字段；双 FIP 时第一行为 FIP1，第二行为 FIP2 |
| `fip1_phase_data` | `float64[samples]` | `float64[samples]` | FIP1 便捷字段 |
| `fip2_phase_data` | 不存在 | `float64[samples]` | FIP2 便捷字段 |
| `fip_sensor_count` | `1` | `2` | 当前文件包含的 FIP 传感器数量 |
| `comm_count` | `int` | `int` | 当前 chunk 最后一包的通信号 |
| `timestamp` | `float` | `float` | 当前文件起始时间，按当前存储会话已保存时长推算 |
| `sample_rate` | `float` | `float` | 每一路 FIP 存储采样率，等于 `raw_sample_rate_hz / 5`；默认 `200000.0` |
| `raw_sample_rate_hz` | `float` | `float` | Tab1 `采样率(MHz)` 换算得到的单路原始采样率 |
| `packet_duration_seconds` | `float` | `float` | Tab1 `单包时长(s)` |
| `format_version` | `wb-monitor-tab1-fip-v1` | `wb-monitor-tab1-fip-v2` | Tab1 FIP 存储格式版本 |
| `data_info` | dict | dict | 元数据，见下表 |

`data_info` 关键字段：

| 字段 | 说明 |
|---|---|
| `type` | 当前为 `phase_unwrapped_downsampled` |
| `length` / `samples_per_sensor` | 每一路 FIP 的样本数 |
| `total_values` | 文件中保存的总数值个数；双 FIP 时约为 `2 * samples_per_sensor` |
| `sensor_count` | 当前文件内 FIP 传感器数量 |
| `downsample_factor` | 固定为 `5` |
| `raw_sample_rate_hz` | 单路 FIP 原始采样率 |
| `packet_duration_seconds` | 单个 FIP TCP 包对应的采集时长 |
| `packet_points_per_sensor` | 单包每路 FIP 原始点数，等于 `round(raw_sample_rate_hz * packet_duration_seconds)` |
| `storage_points_per_packet_per_sensor` | 单包每路 FIP 存储点数，等于 `round(sample_rate * packet_duration_seconds)` |
| `packet_count_estimate` | 当前 chunk 对应的包数估计 |
| `start_comm_count` / `end_comm_count` | 当前 chunk 覆盖的通信号范围 |
| `duration_seconds` | 当前 chunk 时长，按每路样本数和当前 `sample_rate` 计算 |
| `file_sequence` | 当前 Tab1 存储会话内文件序号 |
| `stream_start_time` / `save_time` | 文件时间戳与实际写盘时间 |

双 FIP 模式下，分块时长按“每一路传感器”的样本数计算。例如默认 `采样率=1 MHz`、固定 5x 存储降采样、`存储间隔=10 s` 时，每个文件保存 FIP1 约 `2,000,000` 点和 FIP2 约 `2,000,000` 点，而不是因为两路数据相加而变成 5 秒一个文件。若用户把 FIP 输入采样率改为 `2 MHz`，存储采样率会变为 `400 kHz`，同样 `10 s` 文件会保存每路约 `4,000,000` 点。

## 3. FIP+eDAS 联合存储机制

联合存储的核心是 `AlignedSessionCoordinator`。它以两路数据共有的 `comm_count` 为键，维护一个实时对齐缓存：

```text
Tab1 FIP ProcessedData
  -> DASTab3Manager.process_fip_processed_data()
  -> FIPSessionPacket
  -> AlignedSessionCoordinator.push_fip_packet()

Tab3 DAS TCP payload
  -> DASTCPServer
  -> DASRawPacket
  -> DASTab3Manager._parse_packet()
  -> DASSessionPacket
  -> AlignedSessionCoordinator.push_das_packet()
```

`AlignedSessionCoordinator.get_frames_since(last_comm_count)` 会返回 `comm_count > last_comm_count` 的 `AlignedPacketFrame` 列表。每个 `AlignedPacketFrame` 中同时保留：

- FIP 侧数据：`unwrapped_data`、`display_data`、`sample_rate_hz`、`packet_duration_seconds`。单 FIP 时这就是 FIP1；双 FIP 时这组旧字段指向 Tab1 当前 `绘图FIP` 选择的传感器。`sample_rate_hz` 为 Tab1 处理后的有效采样率，`packet_duration_seconds` 来自 Tab1 `单包时长(s)`。
- FIP 多传感器数据：`sensor_count`、`selected_sensor`、`unwrapped_by_sensor`、`display_by_sensor`。双 FIP 时 `unwrapped_by_sensor[1]` / `[2]` 分别对应 FIP1/FIP2。
- eDAS 侧数据：`matrix`、`channel_count`、`sample_rate_hz`。
- 对齐状态：`fip_missing`、`das_missing`、`packet_start_time`、`packet_duration_seconds`。

当前 joint 存储策略如下：

1. UI 开启 `FIP+eDAS SAVE` 后，Tab3 manager 的 `_storage_timer` 每 1 秒检查一次。
2. 只有 `status.fip_online == True`、`status.das_online == True` 且 `alignment_status == "aligned"` 时，joint 存储才会写入。
3. 若新增帧时长尚未达到 `Joint Length(s)`，UI 状态显示 `Collecting joint chunk ...`，暂不推进 `last_comm_count`，继续等待更多帧。
4. 达到目标时长后，主线程只封装 `DASStorageRequest` 并非阻塞入队；实际 `np.savez_compressed()` 在 `DASStorageWorker` 中完成。
5. `DASStorageWorker.stop()` 现在会先排空已入队请求再退出，降低停止监测时尾部 joint chunk 丢失的风险。

如果用户开启 `FIP+eDAS SAVE` 但当前只有一路通信成功，程序会自动降级到可用的单源保存：

- 只有 eDAS 在线：关闭 joint 按钮，自动开启 Tab3 `eDAS SAVE`。
- 只有 FIP 在线：关闭 joint 按钮，跳转到 Tab1 并勾选 `保存相位数据`，沿用 Tab1 FIP 相位存储链路。
- 两路都未在线：不写 joint 文件，UI 显示等待两路通信。

这种降级只改变后续保存入口，不回填降级前已经过去的历史包。

## 4. joint `.npz` 文件格式

joint 文件名格式：

```text
FIPeDAS-YYYYMMDD-HHMMSS.mmm.npz
```

当前写入字段如下：

| 字段 | 类型 | 说明 |
|---|---|---|
| `comm_counts` | `int32[]` | joint chunk 中的通信包号 |
| `packet_start_times` | `float64[]` | 每帧起始时间，单位秒 |
| `packet_duration_seconds` | `float64[]` | 每帧持续时间，单位秒 |
| `fip_present` | `bool[]` | FIP 数据是否存在 |
| `das_present` | `bool[]` | eDAS 数据是否存在 |
| `fip_raw_200khz` | object array | 兼容旧脚本的 FIP 展开相位序列；2026-07-18 起写入未滤波、已展开、按 `fip_sample_rate_hz` 降采样后的序列；字段名保留历史 `200khz`，实际采样率以 `fip_sample_rate_hz` 为准；双 FIP 时写 Tab1 当前 `绘图FIP` 选择的传感器 |
| `fip_display_data` | object array | 兼容旧脚本的 FIP 显示序列；2026-07-18 起与 `fip_raw_200khz` 保持一致，均为未滤波降采样序列；双 FIP 时写 Tab1 当前 `绘图FIP` 选择的传感器 |
| `fip_sensor_count` | `int32[]` | 每帧 FIP 传感器数量，单 FIP 为 `1`，双 FIP 为 `2` |
| `fip_selected_sensor` | `int32[]` | 兼容旧字段当前对应的 FIP 传感器编号 |
| `fip1_raw_200khz` | object array | FIP1 未滤波、已展开、降采样相位序列；字段名保留历史 `200khz`，实际采样率以 `fip_sample_rate_hz` 为准 |
| `fip2_raw_200khz` | object array | FIP2 未滤波、已展开、降采样相位序列；字段名保留历史 `200khz`，实际采样率以 `fip_sample_rate_hz` 为准；单 FIP 或缺失时为空数组 |
| `fip1_display_data` | object array | FIP1 未滤波显示序列；2026-07-18 起与 `fip1_raw_200khz` 保持一致 |
| `fip2_display_data` | object array | FIP2 未滤波显示序列；2026-07-18 起与 `fip2_raw_200khz` 保持一致；单 FIP 或缺失时为空数组 |
| `das_raw_matrix` | object array | eDAS 矩阵，形状通常为 `channel_count x samples_per_channel` |
| `fip_sample_rate_hz` | `float64[]` | FIP 每帧采样率，新版本新增 |
| `das_sample_rate_hz` | `float64[]` | eDAS 每帧采样率，新版本新增 |
| `das_channel_count` | `int32[]` | eDAS 每帧通道数，新版本新增 |
| `incremental` | `bool` | `True` 表示增量 chunk，不是滑动窗口全量快照 |
| `format_version` | string | 当前为 `wb-monitor-joint-v3` |
| `created_at` | string | 文件创建时间，ISO 毫秒格式 |

新增字段是向后兼容的：旧脚本仍可按 `fip_raw_200khz`、`fip_display_data`、`das_raw_matrix` 等原字段读取；新脚本可优先读取 `fip_sensor_count` 和 `fip1_*` / `fip2_*` 字段来区分两路 FIP。新 Notebook 会优先读取 FIP1/FIP2 分路字段、采样率和通道数字段，缺失时再按兼容字段、样本数和包时长回退。

注意：joint 存储中的 FIP 数据不做猜测性幅值归一化。软件只执行 TCP 协议规定的 `<32,32>` 定点数解码和相位展开；旧代码中按 `max(abs(data)) > 5` 自动除以 `pi` 的逻辑已在 2026-07-18 删除。若发送端数据超出相位展开器期望的包裹范围，软件记录诊断日志，但不擅自缩放幅值。

## 5. eDAS SAVE 独立存储机制

`eDAS SAVE` 的目标是保存 Tab3 DAS TCP 链路接收到的完整 eDAS 数据块，不依赖 FIP 在线状态，也不依赖 GUI 绘图刷新。实现参考 PCIe-7821 项目的以下原则：

- 前台接收线程只做非阻塞入队，不直接写磁盘。
- 后台保存线程串行写文件。
- 按完整块数量分文件，而不是按 GUI 刷新次数或任意字节切分。
- 队列满时丢弃最旧待写块，优先保护 TCP 接收和 UI 响应。

本项目的 eDAS TCP 协议在 `DASTCPServer` 中按 `>i4` 读取 payload（`int32` 相位计数），并立即转换为 `float64` 弧度（`phase_rad = phase_int32 / 32767 * pi`）。因此 `eDAS SAVE` 保存的是 Tab3 已解析后的 `float64` 矩阵，不是 PCIe-7821 项目中 PHASE 模式常见的 `int32` 块。

写入流程：

```text
DAS TCP payload (>i4 int32)
  -> DASTCPServer 解析并转换为 float64 弧度
  -> DASTab3Manager._parse_packet() 得到 channel x sample 矩阵
  -> EDASRawStorageWorker.enqueue_packet() 非阻塞入队
  -> EDASRawStorageWorker 后台写 .bin，并维护同名 .json 元数据
```

## 6. eDAS-only `.bin + .json` 文件格式

`.bin` 文件名格式：

```text
0000001-eDAS-1000Hz-0004ch-0020pt-20260717T015000.000.bin
```

字段含义：

- `0000001`：当前 Tab3 存储会话内文件序号。
- `1000Hz`：eDAS 采样率。
- `0004ch`：通道数。
- `0020pt`：每通道每包样本数。
- 时间戳：文件创建时间。

`.bin` 二进制布局：

```text
block 0: channel 0 samples, channel 1 samples, ..., channel N samples
block 1: channel 0 samples, channel 1 samples, ..., channel N samples
...
```

每个 block 是一个 `channel_count x samples_per_channel` 的 C-order 矩阵，元素类型为 little-endian `float64`。离线读取时可按 JSON 中的 `matrix_shape_per_block` 和 `blocks_written` 恢复为：

```python
raw = np.fromfile(bin_path, dtype='<f8')
blocks = raw.reshape(blocks_written, channel_count, samples_per_channel)
```

同名 `.json` 元数据包括：

| 字段 | 说明 |
|---|---|
| `format_version` | 当前为 `wb-monitor-edas-raw-v1` |
| `storage_type` | `edas_raw_storage` |
| `data_file` / `metadata_file` | 数据文件与元数据文件名 |
| `created_at` / `closed_at` | 文件创建与关闭时间 |
| `output_dir` | 当前 eDAS-only 输出目录 |
| `file_index` | 当前 eDAS-only 会话内文件序号 |
| `dtype` / `byte_order` / `array_order` | 二进制解析方式 |
| `matrix_shape_per_block` | 单个 block 的 `[channel_count, samples_per_channel]` |
| `sample_rate_hz` | eDAS 采样率 |
| `packet_duration_seconds` | 单包持续时间 |
| `blocks_per_file` | UI 中设置的分文件块数 |
| `queue_packets` | UI 中设置的 eDAS 保存队列有效容量 |
| `data_bytes_per_block` | 单个 eDAS 包写入 `.bin` 的字节数 |
| `storage_parameters` | eDAS-only 存储参数快照，包括输出目录、分文件块数、队列容量、分文件策略和队列溢出策略 |
| `das_parameters` | eDAS 采集参数快照，包括采样率、通道数、每通道样本数、包时长、单包字节数和单包矩阵形状 |
| `blocks_written` | 当前文件实际写入块数 |
| `bytes_written` | 当前文件实际写入字节数 |
| `comm_counts` | 当前文件内每个 block 对应的通信号 |
| `packet_start_times` / `packet_end_times` | 每个 block 的起止时间 |
| `block_bytes` | 每个 block 的写入字节数 |

## 7. Space-Time 色标策略

本次修改后，Tab3 的 DAS Space-Time 图不再根据最新矩阵自动更新色标范围。具体行为为：

- 默认 colormap：`Seismic`。
- 默认 `Vmin=-0.3`、`Vmax=0.3`。
- 每次绘图都使用 UI 当前输入的 `Vmin/Vmax`。
- `HistogramLUTWidget` 的显示范围也固定为同一组 `Vmin/Vmax`，不再扩展到数据最小值和最大值。
- 如果用户输入 `Vmin >= Vmax`，代码只做最小必要修正，保证 pyqtgraph 可绘图，不做数据自适应。

该策略适用于需要跨时间、跨实验保持颜色含义一致的 eDAS 对比场景。
