## 新增同步检验实现

### 数据记录

1. FIP 每收到一个 TCP 包，在 `PCCPMonitorApp._process_data_packet()` 中调用：

```python
self.main_window.record_fip_packet_receive(packet.comm_count, time.time())
```

2. eDAS 每解析一个 TCP 包，在 `DASTab3Manager._handle_raw_packet()` 中调用：

```python
self.main_window.record_edas_packet_receive(parsed.header.comm_count, time.time())
```

3. 两个模块的接收时间按 `comm_count` 分别缓存，缓存上限为 `2000` 个序号，避免长时间运行占用过多内存。

### 显示指标

Data tab 中实时显示以下字段：

1. `首次包时间差`：首个匹配 `comm_count` 的 `eDAS接收时间 - FIP接收时间`。
2. `最新同序号包时间差`：最新匹配 `comm_count` 的 `eDAS接收时间 - FIP接收时间`。
3. `平均时间差`：当前所有匹配包的平均接收时间差。
4. `已匹配包数`：已同时收到 FIP 和 eDAS 的相同 `comm_count` 数量。

### 判读方法

1. 若两套设备物理同步采集、每包长度均为 `1 s`，且同时启动通信，则同序号包的时间差理论上应接近 `0 s`。
2. 如果首次包时间差稳定偏大，通常表示两个模块并未真正同时启动、某一侧先开始发送或接收端连接建立较晚。
3. 如果最新包时间差随运行时间持续漂移，可能表示两侧包周期或计数基准不一致。
4. 如果平均时间差稳定但有少量尖峰，优先检查主机调度、网络抖动和 GUI 主线程压力。
5. 当前实现使用主机接收时间，不是设备硬件时间戳；它适合联调阶段验证通信同步表现，不能替代设备内部时钟校准。
