# 关闭 Tab2 时空图后的切页卡顿与布局修复

依据：`logs/pccp_monitor_2026-10-23_13-00-37.log`；日期：2026-10-23，分支 dev2。

## 日志能证明什么

- 日志 297 行，13:01:41 明确记录关闭 Tab2 时空图，显示请求为 `mode=1`（SPACE）、`region=100`、`incremental_full_width=0`。
- 此前采集测得约 99800 fps，接近配置 100000 Hz；此后多次读取循环持续 3.3～5.5 s，停止前帧率统计约 39890.6 fps，驱动积压约 7.87 s。
- 联合保存共有 27 次成功记录，中位数 151.96 ms，最大 10495.08 ms。13:01:41 开始的一个写入耗时 4350.61 ms。不能据此把写入耗时全部解释成磁盘物理速度，调度、内存、系统/DLL 等等待也包含在墙钟耗时中。
- 13:02:19 出现唯一 ERROR：联合未写入缓存超过 2 GiB，触发停止保护。之后仍有未写入缓存警告和 FIP 未收完整包警告。
- 13:02:34 开始停止 eDAS，日志末尾 13:02:45 仍有一次 10495 ms 写入完成；未记录完整 pipeline stopped/cleanup。**不能宣称这次所有数据已保存，也不能只把它视为显示丢帧。**
- 当时系统可用内存仍约 118 GB，不支持直接认定物理内存耗尽。没有卡住瞬间的线程栈，也不能唯一确定 DLL 读取、磁盘、GUI 或其他系统等待谁是最初原因。

## 已修复的显示路径

原先关闭时空图会切换显示数据形状，退回旧 GUI 显示处理路径。SPACE 会把完整采样率单通道曲线交给 GUI 滤波与绘制；TIME 且滤波开启时还会在 GUI 线程对完整时间×通道矩阵滤波。**现场日志是 SPACE，不能把 TIME 的整矩阵分支直接认定为本次唯一根因。**

关闭时空图后现改用独立的精简快照 `snapshot_kind=4`：

1. 在采集线程准备所选通道的时间波形和末帧空间剖面，不生成隐藏时空图。
2. SPACE 仅滤波所选通道；TIME 需要空间各通道时分块处理，每个浮点工作块受限，最终只向 GUI 发送一条时间曲线和一帧空间剖面。
3. GUI 不再对这一快照重复缩放或滤波，曲线限制约 5000 点，再按可见 PSD 开关计算相应频谱。
4. 图像显示、模式、通道及可见性切换会在采集线程下一显示块边界重置显示历史/滤波状态，避免新旧形状混用。
5. 继续保持只刷新当前页；切页和显示开关不修改原始采集数据、共享数据或存储算法。

增加 GUI 心跳诊断：主线程每 2 s 重置原生 8 s 栈转储计时器。若事件循环长时间不响应，faulthandler 自动向 `logs/crash_reports/crash_*.log` 写所有线程堆栈，恢复后继续心跳；正常退出前取消计时器。转储不强制结束程序、不代替写盘保护。长时间阻塞的同步 Stop 也可能留下 Timeout 栈，可用于区分排空等待和其他卡顿。

## 布局调整

- Tab1 PSD 总开关关闭时，两张 PSD 控件隐藏，两条波形跨越原 PSD 列；单独取消 PSD1/PSD2 也分别收回该行空白。
- Tab1 参数区默认 448→314 px，约缩小 30%，可调范围 280～720 px。Tab2 继续联动宽度；窄屏摘要和提示换行。旧配置中恰为旧默认 448 px 的宽度首次迁移为 314 px，其他自定义宽度保留；新配置使用宽度 schema=2。
- 主 Tab 栏绘制时移除原生焦点矩形，保留图标、选择高亮、点击与键盘切换行为。
