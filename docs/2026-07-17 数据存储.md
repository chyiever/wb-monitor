# 2026-07-17 数据存储

## 1. 文档目的

本文档面向开发者，说明当前 `wb-monitor` 版本中 Tab3 原始数据存储的实现机制、文件格式、线程模型、UI 参数和离线读取方式。文档覆盖两条链路：

1. `FIP+eDAS SAVE`：FIP 与 eDAS 联合存储，沿用原 Tab3 joint storage 设计，以 `comm_count` 对齐两类数据并写入 `.npz`。
2. `eDAS SAVE`：新增 eDAS 独立原始存储，参考 `E:\codes\PCIe-7821\pcie7821_gui\src\data_saver.py` 与 `docs\README-2026-03-20-eDAS数据存储技术说明.md` 的后台队列、分文件、非阻塞入队思路实现。

本次实现还同步调整了 Tab3 左侧参数区布局，以及 DAS Space-Time 图色标策略：默认 `Seismic`，默认 `Vmin=-0.3`、`Vmax=0.3`，后续绘图不再根据数据自动改写手动输入范围。

## 2. Tab3 raw storage UI

Tab3 左侧存储区域标题由 `Joint Raw Storage` 改为 `raw storage`。该区域包含两个可同时开启的保存按钮：

- `FIP+eDAS SAVE`：联合保存 FIP 与 eDAS 数据。
- `eDAS SAVE`：只保存 Tab3 接收到的 eDAS 原始矩阵数据。

两条存储链路互相独立：

- `FIP+eDAS SAVE` 由 `DASStorageWorker` 后台线程写 `.npz`。
- `eDAS SAVE` 由 `EDASRawStorageWorker` 后台线程写 `.bin + .json`。
- 两个按钮可以同时打开。此时 eDAS 每个 TCP 包会进入 eDAS-only 队列，同时达到联合保存条件后，FIP/eDAS 对齐帧会进入 joint 队列。

UI 参数含义如下。为避免左侧参数区出现滚动条，当前布局已经将短标签参数尽量合并到同一行：通信状态、Live Header、Alignment、Curve、Space-Time 与 raw storage 参数均采用紧凑网格；`FIP+eDAS Path` 和 `eDAS Path` 与路径输入框在同一行显示。

| 参数 | 作用 | 当前默认值 |
|---|---|---:|
| `FIP+eDAS Path` | joint `.npz` 输出目录 | `D:/PCCP/FIPeDASDATA` |
| `Joint Length(s)` | 每个 joint chunk 目标时长，达到该时长后入队写盘 | `10.0` |
| `Joint Cache(s)` | 对齐协调器保留的最近数据时长，代码会保证至少大于 joint chunk 时长 | `10.0` |
| `eDAS Path` | eDAS-only `.bin + .json` 输出目录 | `D:/PCCP/eDASDATA` |
| `Blocks/File` | 每个 eDAS-only `.bin` 文件包含多少个 DAS 包/块 | `50` |
| `Cache(packets)` | eDAS-only 保存队列的有效容量，队列满时丢弃最旧包 | `200` |

## 3. FIP+eDAS 联合存储机制

联合存储的核心是 `AlignedSessionCoordinator`。它以两路数据共有的 `comm_count` 为键，维护一个实时对齐缓存：

```text
Tab1 FIP ProcessedData
  -> DASTab3Manager.process_fip_processed_data()
  -> FIPSessionPacket
  -> AlignedSessionCoordinator.push_fip_packet()

Tab3 DAS TCP payload
  -> DASTCPServer
  -> DASRawPacket
  -> DASTab3Manager._parse_packet()
  -> DASSessionPacket
  -> AlignedSessionCoordinator.push_das_packet()
```

`AlignedSessionCoordinator.get_frames_since(last_comm_count)` 会返回 `comm_count > last_comm_count` 的 `AlignedPacketFrame` 列表。每个 `AlignedPacketFrame` 中同时保留：

- FIP 侧数据：`unwrapped_data`、`display_data`、`sample_rate_hz`。
- eDAS 侧数据：`matrix`、`channel_count`、`sample_rate_hz`。
- 对齐状态：`fip_missing`、`das_missing`、`packet_start_time`、`packet_duration_seconds`。

当前 joint 存储策略如下：

1. UI 开启 `FIP+eDAS SAVE` 后，Tab3 manager 的 `_storage_timer` 每 1 秒检查一次。
2. 只有 `status.fip_online == True`、`status.das_online == True` 且 `alignment_status == "aligned"` 时，joint 存储才会写入。
3. 若新增帧时长尚未达到 `Joint Length(s)`，UI 状态显示 `Collecting joint chunk ...`，暂不推进 `last_comm_count`，继续等待更多帧。
4. 达到目标时长后，主线程只封装 `DASStorageRequest` 并非阻塞入队；实际 `np.savez_compressed()` 在 `DASStorageWorker` 中完成。
5. `DASStorageWorker.stop()` 现在会先排空已入队请求再退出，降低停止监测时尾部 joint chunk 丢失的风险。

如果用户开启 `FIP+eDAS SAVE` 但当前只有一路通信成功，程序会自动降级到可用的单源保存：

- 只有 eDAS 在线：关闭 joint 按钮，自动开启 Tab3 `eDAS SAVE`。
- 只有 FIP 在线：关闭 joint 按钮，跳转到 Tab1 并勾选 `保存相位数据`，沿用 Tab1 FIP 相位存储链路。
- 两路都未在线：不写 joint 文件，UI 显示等待两路通信。

这种降级只改变后续保存入口，不回填降级前已经过去的历史包。

## 4. joint `.npz` 文件格式

joint 文件名格式：

```text
FIPeDAS-YYYYMMDD-HHMMSS.mmm.npz
```

当前写入字段如下：

| 字段 | 类型 | 说明 |
|---|---|---|
| `comm_counts` | `int32[]` | joint chunk 中的通信包号 |
| `packet_start_times` | `float64[]` | 每帧起始时间，单位秒 |
| `packet_duration_seconds` | `float64[]` | 每帧持续时间，单位秒 |
| `fip_present` | `bool[]` | FIP 数据是否存在 |
| `das_present` | `bool[]` | eDAS 数据是否存在 |
| `fip_raw_200khz` | object array | FIP 展开相位原始序列 |
| `fip_display_data` | object array | FIP 显示降采样序列 |
| `das_raw_matrix` | object array | eDAS 矩阵，形状通常为 `channel_count x samples_per_channel` |
| `fip_sample_rate_hz` | `float64[]` | FIP 每帧采样率，新版本新增 |
| `das_sample_rate_hz` | `float64[]` | eDAS 每帧采样率，新版本新增 |
| `das_channel_count` | `int32[]` | eDAS 每帧通道数，新版本新增 |
| `incremental` | `bool` | `True` 表示增量 chunk，不是滑动窗口全量快照 |
| `format_version` | string | 当前为 `wb-monitor-joint-v2` |
| `created_at` | string | 文件创建时间，ISO 毫秒格式 |

新增字段是向后兼容的：旧脚本仍可按原字段读取；新 Notebook 会优先读取采样率和通道数字段，缺失时再按样本数和包时长反推。

## 5. eDAS SAVE 独立存储机制

`eDAS SAVE` 的目标是保存 Tab3 DAS TCP 链路接收到的完整 eDAS 数据块，不依赖 FIP 在线状态，也不依赖 GUI 绘图刷新。实现参考 PCIe-7821 项目的以下原则：

- 前台接收线程只做非阻塞入队，不直接写磁盘。
- 后台保存线程串行写文件。
- 按完整块数量分文件，而不是按 GUI 刷新次数或任意字节切分。
- 队列满时丢弃最旧待写块，优先保护 TCP 接收和 UI 响应。

本项目的 eDAS TCP 协议在 `DASTCPServer` 中按 `>f8` 读取 payload，并立即转成本机 `float64`。因此 `eDAS SAVE` 保存的是 Tab3 已解析后的 `float64` 矩阵，不是 PCIe-7821 项目中 PHASE 模式常见的 `int32` 块。

写入流程：

```text
DAS TCP payload (>f8)
  -> DASTCPServer 解析为 DASRawPacket
  -> DASTab3Manager._parse_packet() 得到 channel x sample 矩阵
  -> EDASRawStorageWorker.enqueue_packet() 非阻塞入队
  -> EDASRawStorageWorker 后台写 .bin，并维护同名 .json 元数据
```

## 6. eDAS-only `.bin + .json` 文件格式

`.bin` 文件名格式：

```text
0000001-eDAS-1000Hz-0004ch-0020pt-20260717T015000.000.bin
```

字段含义：

- `0000001`：当前 Tab3 存储会话内文件序号。
- `1000Hz`：eDAS 采样率。
- `0004ch`：通道数。
- `0020pt`：每通道每包样本数。
- 时间戳：文件创建时间。

`.bin` 二进制布局：

```text
block 0: channel 0 samples, channel 1 samples, ..., channel N samples
block 1: channel 0 samples, channel 1 samples, ..., channel N samples
...
```

每个 block 是一个 `channel_count x samples_per_channel` 的 C-order 矩阵，元素类型为 little-endian `float64`。离线读取时可按 JSON 中的 `matrix_shape_per_block` 和 `blocks_written` 恢复为：

```python
raw = np.fromfile(bin_path, dtype='<f8')
blocks = raw.reshape(blocks_written, channel_count, samples_per_channel)
```

同名 `.json` 元数据包括：

| 字段 | 说明 |
|---|---|
| `format_version` | 当前为 `wb-monitor-edas-raw-v1` |
| `storage_type` | `edas_raw_storage` |
| `data_file` / `metadata_file` | 数据文件与元数据文件名 |
| `created_at` / `closed_at` | 文件创建与关闭时间 |
| `output_dir` | 当前 eDAS-only 输出目录 |
| `file_index` | 当前 eDAS-only 会话内文件序号 |
| `dtype` / `byte_order` / `array_order` | 二进制解析方式 |
| `matrix_shape_per_block` | 单个 block 的 `[channel_count, samples_per_channel]` |
| `sample_rate_hz` | eDAS 采样率 |
| `packet_duration_seconds` | 单包持续时间 |
| `blocks_per_file` | UI 中设置的分文件块数 |
| `queue_packets` | UI 中设置的 eDAS 保存队列有效容量 |
| `data_bytes_per_block` | 单个 eDAS 包写入 `.bin` 的字节数 |
| `storage_parameters` | eDAS-only 存储参数快照，包括输出目录、分文件块数、队列容量、分文件策略和队列溢出策略 |
| `das_parameters` | eDAS 采集参数快照，包括采样率、通道数、每通道样本数、包时长、单包字节数和单包矩阵形状 |
| `blocks_written` | 当前文件实际写入块数 |
| `bytes_written` | 当前文件实际写入字节数 |
| `comm_counts` | 当前文件内每个 block 对应的通信号 |
| `packet_start_times` / `packet_end_times` | 每个 block 的起止时间 |
| `block_bytes` | 每个 block 的写入字节数 |

## 7. Space-Time 色标策略

本次修改后，Tab3 的 DAS Space-Time 图不再根据最新矩阵自动更新色标范围。具体行为为：

- 默认 colormap：`Seismic`。
- 默认 `Vmin=-0.3`、`Vmax=0.3`。
- 每次绘图都使用 UI 当前输入的 `Vmin/Vmax`。
- `HistogramLUTWidget` 的显示范围也固定为同一组 `Vmin/Vmax`，不再扩展到数据最小值和最大值。
- 如果用户输入 `Vmin >= Vmax`，代码只做最小必要修正，保证 pyqtgraph 可绘图，不做数据自适应。

该策略适用于需要跨时间、跨实验保持颜色含义一致的 eDAS 对比场景。

## 8. 离线读取工具

已新增 Notebook：

```text
read/fip_edas_joint_reader.ipynb
```

Notebook 用于读取 `FIP+eDAS SAVE` 生成的 joint `.npz` 文件，功能包括：

1. 输出 joint 文件字段列表。
2. 输出 FIP 与 eDAS 采集参数，包括帧数、`comm_count` 范围、包时长、FIP 采样率、FIP 每帧样本数、eDAS 采样率、eDAS 通道数、eDAS 每通道样本数。
3. 绘制 FIP 时域曲线。
4. 绘制 FIP PSD。
5. 绘制 eDAS Space-Time 图。
6. 绘制指定 eDAS channel 的时域曲线。
7. 绘制指定 eDAS channel 的 PSD。

Notebook 兼容旧 joint 文件：如果旧文件没有 `fip_sample_rate_hz`、`das_sample_rate_hz` 或 `das_channel_count`，会用每帧样本数和 `packet_duration_seconds` 反推关键参数。
