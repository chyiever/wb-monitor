## 修复与优化

### 1. Tab2 特征窗口时间轴修复

问题：

- `FIPFeatureWorker` 检测到 `comm_count` 不连续后会清空信号缓存，但没有同步重置 `_window_index`。
- 后续特征帧的 `start_time` 由 `_window_index * hop` 推导，丢包或发送端重启后可能继续沿用上一段窗口序号。
- 影响范围包括特征曲线时间、告警事件时间、触发存储截取范围。

处理：

- 空数据包直接跳过，避免空数组进入滤波与滑窗计算。
- `comm_count` 正向跳跃和倒序/重启分别记录，避免出现负数 `missing`。
- 丢包或重启后同时重置 `_stream_sample_index`、`_window_index`、窗口缓存和滤波状态。
- 特征窗口 `start_time` 改为由 `_next_window_start_index / sample_rate` 直接推导，避免窗口序号和样本位置分离。

结果：

- Tab2 时间轴以 `comm_count * packet_duration + 样本偏移` 为准。
- 丢包后不会跨缺口拼接滑动窗口。
- 告警事件和触发存储使用同一套修正后的时间基准。

### 2. Tab2 触发存储窗口修复

问题：

- 后触发窗口此前使用 `event.start_time + post_trigger_seconds` 作为结束边界。
- 当一次异常事件持续时间较长时，保存片段可能覆盖不到事件后半段。
- 停机排空时，如果后触发窗口尚未等满，pending request 可能在停止流程中丢失。

处理：

- 后触发等待条件改为 `event.end_time + post_trigger_seconds`。
- 保存片段结束时间同步改为 `event.end_time + post_trigger_seconds`。
- 进入 drain 模式时，即使后触发窗口没有完全等满，也保存当前已缓存数据并写告警日志。

结果：

- 长事件的触发片段覆盖完整事件。
- 停机时不会静默丢失活跃告警事件。

### 3. Tab1 FIP 通信序号异常分类

问题：

- Tab1 数据处理线程把所有非 `last + 1` 的序号变化都按缺包处理。
- 当发送端或 TCP 会话重启导致 `comm_count` 回退时，日志中可能出现负数 `missing`，误导现场判断。

处理：

- 正向跳跃才计入缺包统计。
- 倒序或重启单独记录为 reset/out-of-order，并重置每传感器处理状态。

结果：

- 缺包统计更准确。
- 重启场景不再污染丢包计数。

### 4. Tab1 原始存储顺序保护

问题：

- FIP 存储路径在收到重复或倒序包时仍可能继续追加到当前 chunk。
- 极端情况下会造成同一个 NPZ 文件内 `comm_count` 回退，影响离线分析的时间顺序。

处理：

- 重复/倒序包默认丢弃并计入 `raw_packets_duplicate_or_out_of_order`。
- 若检测到新会话归零（`comm_count == 0`），先 flush 当前 chunk，再清空缓存并开始新存储段。

结果：

- 单个存储文件内不再混入明显倒序包。
- 同一监测周期内重新连接时，已有缓存可先落盘，新会话从新段开始。

### 5. 联合存储元数据健壮性

问题：

- `build_chunk_metadata()` 原先从 chunk 第一帧提取 FIP/eDAS 顶层元数据。
- 如果第一帧缺某一路，但后续帧存在该路数据，顶层通道数/采样率可能被写成 0。

处理：

- 顶层 FIP/eDAS 元数据改为从 chunk 内首个实际存在的 FIP/eDAS packet 提取。
- 每帧级别的 `fip_present`、`das_present` 字段保持不变。

结果：

- 局部缺帧不会污染整个文件的顶层元数据。
- 离线读取器可以更可靠地识别数据源参数。

### 6. 长时间运行状态缓存裁剪

问题：

- UI 同步统计中的 `_sync_matched_counts` 仅用于去重，长时间运行会持续增长。

处理：

- 与接收时间缓存相同，保留最近 2000 个匹配序号。
- 首包匹配序号保留，确保首包时间差显示不受裁剪影响。

结果：

- 长时间运行内存占用更稳定。
- 首包、最新和平均同步统计逻辑保持兼容。

### 7. 低风险旧调试代码清理

处理内容：

- 删除 FIP TCP、FIP 处理链路和 DAS 管理链路中对“首点为 0”的旧调试告警。
- 删除 `src/fip/tcp_server.py` 中未使用的 `psutil`、`os` 导入。

原因：

- 第一个采样点为 0 在实际采集中可能是合法值。
- 旧告警在联调日志中容易形成噪声，不适合作为数据异常依据。
