## 问题排序

### S1 操作/参数问题，跳过程序修复

1. FIP TCP 多次收到 `data_length=16000000`，而当前程序阈值拒绝该包长，共 19 条 `ERROR`。
2. DAS TCP 绑定了本机不存在或不可用的 IP，导致 `[WinError 10049]`，DAS 服务启动失败 2 次，并引发主控 Tab3 启动失败 2 次。

结论：这两类问题来自联调参数、发送端程序或本机 IP 选择，不属于当前软件逻辑缺陷。本轮未改 FIP TCP 包长阈值，也未改 DAS 绑定策略。

### S2 Tab2 触发存储排空超时，已梳理，按要求暂不修复

日志末尾出现 1 条 `WARNING`：`Tab2 storage drain timeout: some trigger events may not have been saved.`

原因梳理：

1. Tab2 触发存储需要等待告警事件后的 `post_trigger_seconds` 数据窗口。
2. 停机时日志显示 `pending=1`，说明仍有一个触发保存请求在等待后触发窗口。
3. 如果此时采集停止或等待时间不足，存储线程会持续等待 `_latest_time` 追上目标窗口，最终触发 5 秒排空超时。
4. 可选修复方向是停机时保存“已采集到的部分后触发数据”，并在 `.npz` 元数据中标注是否完整；但用户已明确要求先跳过、不修复。

结论：本轮未修改 `src/fip_tab2/fip_trigger_storage.py` 与 `src/fip_tab2/fip_tab2_manager.py` 的排空逻辑。

### S3 Tab2 无总控入口，默认随 FIP 监测启动，已修复

问题：原程序在 FIP 监测启动时无条件启动 Tab2 特征提取、检测、绘图和触发存储线程。联调阶段如果只需要 Tab1 或 FIP-eDAS 基础链路，Tab2 会额外消耗 CPU、产生告警/存储侧影响，并触发上述停机排空风险。

解决方案：

1. 在 Tab2 左侧参数区顶部新增总控按钮 `Start Tab2`。
2. 按钮默认未选中，因此默认不启动 Tab2。
3. 点击后按钮切换为 `Stop Tab2`，程序允许 Tab2 线程启动和接收数据。
4. 主程序增加 Tab2 开关守卫：未开启时不启动 Tab2 线程，不把 Tab1 处理后的数据转发给 Tab2。
5. 运行中关闭按钮时，如果 Tab2 正在运行，则停止 Tab2 管线并清空 Tab2 特征图。

涉及文件：

- `src/ui/main_window.py`
- `src/main.py`

### S4 日志文件编码未显式指定，已修复

问题：Windows 下 `logging.FileHandler` 未显式指定编码时会使用系统默认编码。按 UTF-8 读取历史日志时，中文系统错误信息会显示为替换字符，影响后续日志分析。

解决方案：将 `src/main.py` 中 `logging.FileHandler(log_dir / 'pccp_monitor.log')` 改为 `logging.FileHandler(log_dir / 'pccp_monitor.log', encoding='utf-8')`。

说明：历史日志中已经写入的乱码无法自动恢复；本修复保证后续新日志按 UTF-8 写入。
