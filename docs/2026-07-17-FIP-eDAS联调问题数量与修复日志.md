   - `update_tab3_fip_curve()` 每个 FIP 包都在 Qt 主线程绘制约 40000 点 FIP 对比曲线。

1. 参照 `E:\codes\PCIe-7821\pcie7821_gui` 中 Tab2 Time-Space 图和 Tab1 phase 时域图的更新机制，将 Tab3 Space-Time 改为固定大小 `float32` 滚动显示缓存。

5. Space-Time 每帧只更新图像本体和必要的 `rect`；色标、`Vmin/Vmax` 和 Histogram 范围改为由参数变更时更新，不再每帧重设。
6. PyQtGraph 曲线继续启用 `setClipToView(True)`、自动 peak downsampling 和 `setSkipFiniteCheck(True)` 的快速路径。

### S11 FIP 包点数与 UI 采样率不一致，已修复运行采样率推导

问题：

1. 本次半天测试中，UI 记录 Tab1 FIP 为单 FIP、`1 s`、`1 MHz`。
2. 但 TCP 实际每包为 `2,000,000` 点，单 FIP 模式下按 `1 s` 计算应对应 `2 MHz`，而不是 UI 标称的 `1 MHz`。
3. 旧代码在单 FIP 模式下不会校验 `实际点数 == sample_rate_hz * packet_duration_seconds`，会直接把全部 `2,000,000` 点作为 FIP1 处理，同时仍按 `1 MHz / 5 = 200 kHz` 写入 `effective_rate`。
4. 该问题不会造成 TCP 字节丢失，但会造成 FIP 时间轴、PSD 频率轴、Tab3 FIP 曲线和 joint `.npz` 元数据采样率标错一倍，属于数据完整性中的元数据一致性问题。

日志证据：

```text
FIP input settings updated: sensor_count=1 selected=FIP1 duration=1.000000s sample_rate=1000000.0Hz
FIP_TCP_PARSE comm=46000 raw_comm=46000 points=2000000 ...
FIP_PROCESS_SENSOR ... input=2000000 ... effective_rate=200000.0
```

修复：

1. `PCCPMonitorApp._process_data_packet()` 新增 FIP 包形状校验。
2. 当 `实际点数` 与 `sensor_count * sample_rate_hz * packet_duration_seconds` 偏差超过 1% 且可按传感器数量整除时，按 `actual_points_per_sensor / packet_duration_seconds` 推导运行采样率。
3. 新增 `FIP_PACKET_SHAPE_MISMATCH` 日志，记录配置采样率、期望点数、实际点数、每路实际点数和推导采样率。
4. 推导采样率会同步到滤波器、Tab1 处理线程、Tab1 存储线程、Tab3 FIP 曲线和 joint 存储元数据。
5. 当后续包形状重新匹配 UI 设置时，自动清除运行采样率 override，并恢复 UI 标称采样率。

本次日志对应修复后的预期行为：

- 单 FIP、`1 s`、实收 `2,000,000` 点时，运行采样率推导为 `2,000,000 Hz`。
- 当前 5x 降采样下，未滤波 FIP 输出和 joint 存储的 `fip_sample_rate_hz` 应为 `400,000 Hz`。

### S15 TCP UI 统计包率口径仍有隐患，已修复
