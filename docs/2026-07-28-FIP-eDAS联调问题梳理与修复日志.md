# 2026-07-28 FIP-eDAS联调问题梳理与修复日志

## 一、问题背景

本次问题来自现场测试日志：

- `logs/pccp_monitor_2026-07-28_12-15-53.log`
- 测试过程：第一次启动时 eDAS 未开通信，仅 FIP 数据进入；停止后重新测试，FIP 与 eDAS 同时进入。
- 用户观察：
  1. FIP 波形显示很粗，怀疑相位展开或绘图链路有问题。
  2. 软件运行几秒后卡顿，鼠标出现小圆圈。
  3. View/Tab1 波形一放大界面卡死。
  4. GUI 每行参数显示不全，相邻行上下字符遮挡。
  5. 全局显示设置修改后需要重启才能生效，希望立即生效。
  6. FIP 数据默认不乘以 `π`；“乘以 `π`”和“相位展开”必须通过 GUI 勾选框成套控制。

## 二、日志证据与问题优先级

### P0：FIP 默认相位处理链路错误

日志中 FIP 原始解析值为工程量级：

- `FIP_TCP_PARSE comm=0 ... decoded_range=[-1029.19785,-833.25919]`
- `FIP phase input ... outside normalized [-1, 1]`
- 随后仍进入 `PhaseUnwrapper`，并输出 `unwrapped=... range=[-1029.19319,-1028.06823]`

这说明当前链路默认把 FIP 当作需要相位展开的数据处理。对现场已经是工程相位或弧度量级的数据，这会改变原始形态，造成波形显示不符合预期。

### P1：实时绘图负载过高导致卡顿

eDAS 同时进入后，日志出现多次慢帧：

- `TAB3_NODE das_tcp.slow_receive ... receive_ms=4856.97`
- `TAB3_NODE plot_worker.slow ... elapsed_ms=2694.19 curve_points=5000 matrix_shape=(51, 5000)`
- `TAB3_NODE plot_worker.enqueue drop_oldest`

这说明接收、重组、曲线、空间时间图和 UI 刷新同时工作时，绘图侧已经出现秒级耗时峰值。即使 TCP 接收线程独立，Qt 信号和 UI 绘图仍会争用主线程。

### P2：缩放时自动范围与高密度曲线重绘冲突

View 曲线使用 pyqtgraph `setData` 实时刷新。缩放时若仍启用自动范围，实时 `setData` 会持续触发布局、范围、PSD 缓存刷新，导致用户缩放操作和后台刷新互相抢占，表现为界面卡死。

### P3：GUI 行高不足与全局设置非即时生效

当前 GUI 默认字号较大，但 SpinBox、ComboBox、按钮、复选框、标签的最小高度和布局间距没有按字号同步调整，导致参数行上下字符遮挡。全局显示设置虽然能保存，但运行时应用不完整，用户需要重启才能看到稳定效果。

## 三、FIP 与 eDAS 数据流

### FIP 数据流

1. `src/fip_tab1/fip_tcp_server.py`
   - 监听 FIP TCP 端口。
   - 接收一包 FIP 原始 payload。
   - 解析通信序号、原始大端 `int64` 定点相位值，并按 Q40.24，即 `raw_int64 / 2^24`，解码为 `phase_data`。

2. `src/main.py::_process_data_packet`
   - 收到 TCP server 的 FIP 包。
   - 读取 GUI 中的 FIP 数量、选中 FIP、单包时长、采样率、相位展开开关。
   - 根据实际点数和 GUI 参数推断真实采样率，避免时间轴错误。
   - 构造 `RawDataPacket` 并送入 Tab1 线程管理器。

3. `src/fip_tab1/fip_tab1_manager.py::DataProcessingThread`
   - 按 FIP 数量拆分 FIP1/FIP2；双 FIP payload 按采样点交织顺序拆分：`FIP1[0], FIP2[0], FIP1[1], FIP2[1]...`。
   - 修复明显非有限值或极端异常值。
   - 默认路径：原始 FIP 数值原样进入后续链路，不乘 `π`，不相位展开。
   - 勾选 `FIP相位展开` 后：执行 `phase * π`，再执行 `np.unwrap`，即“乘 `π` + 相位展开”成套启用。
   - 对每一路 FIP 独立应用滤波和降采样，生成显示曲线；选中 FIP 只决定主输出和 PSD 默认源。
   - 生成 `psd_data`，供 View 的 PSD 或联动显示使用。

4. `src/das_tab3/das_tab3_manager.py::process_fip_processed_data`
   - 接收 Tab1 已处理 FIP 包。
   - 推入 FIP/eDAS 对齐协调器。
   - 将 FIP 曲线数据发送到 View 页面。
   - 供 FIP+eDAS 联合存储读取最近缓存。

5. `src/fip_tab1/fip_tab1_manager.py::DataStorageThread`
   - FIP 存储开启时，独立线程从原始包队列构建存储窗口。
   - 默认存储 `phase_raw_downsampled`。
   - 勾选相位展开后存储 `phase_unwrapped_downsampled`，并写入 `phase_unwrap_enabled` 元数据。

### eDAS 数据流

1. `src/das_tab3/das_tcp_server.py`
   - 监听 eDAS TCP 端口。
   - 读取固定 header：`comm_count / sample_rate_hz / channel_count / data_bytes / packet_duration_seconds`。
   - 按 `data_bytes` 读取 payload，并转换为 `float64` 一维数据。

2. `src/das_tab3/das_tab3_manager.py::_handle_raw_packet`
   - 校验 payload 点数与通道数。
   - reshape 为二维矩阵：`channel_count x samples_per_channel`。
   - 生成 `DASParsedPacket`。
   - 推入 FIP/eDAS 对齐协调器。
   - eDAS 存储开启时送入 eDAS 原始存储线程。
   - 始终送入 eDAS 绘图 worker 队列。

3. `src/das_tab3/das_plot_worker.py`
   - 从最近 eDAS 包历史中抽取曲线通道。
   - 按曲线点数预算降采样。
   - 构建空间时间图滚动矩阵。
   - 按像素预算自动提高时间降采样，避免矩阵过大。
   - 发送 plot-ready payload 给主线程 UI。

4. `src/ui/main_window.py::update_tab3_plot_payload`
   - 更新 eDAS 曲线。
   - 更新空间时间图 `ImageItem`。
   - 当 View 页面不在前台或刷新开关关闭时跳过重绘。

5. 联合对齐与存储
   - `alignment.AlignedSessionCoordinator` 以 FIP/eDAS 的 `comm_count` 和接收时间维护对齐状态。
   - `DASTab3Manager._maybe_store_snapshot` 在 FIP/eDAS 均在线且满足对齐条件时写入联合 npz。

## 八、23:01 FIP 幅值缩放与每秒起点尖跳分析修复

日志文件：

- `logs/pccp_monitor_2026-07-28_23-01-56.log`

现场现象：

- FIP 设备端原始数据显示：
  - FIP1 约在 `194000` 上下波动。
  - FIP2 约在 `26300` 上下波动。
- 本软件显示两路都在 `430` 上下波动。
- 时域波形看起来每 1 s 更新一次，且每次起点位置存在尖跳。

日志证据：

- 软件当时仍使用旧解码比例，`raw_int64 / 2^32`：
  - `raw_first=3316069512861`
  - 旧解码：`3316069512861 / 2^32 = 772.082599`
  - 若按设备端量级使用 Q40.24：`3316069512861 / 2^24 = 197653.145365`
- FIP2 低值同样吻合 Q40.24：
  - `raw_min=478403643438`
  - 旧解码：`478403643438 / 2^32 = 111.387028`
  - Q40.24 解码：`478403643438 / 2^24 = 28515.079226`
- 日志中 FIP1/FIP2 的 `input range` 都覆盖了高值和低值：
  - FIP1：`range=[108.932709,774.574746]`
  - FIP2：`range=[108.863893,775.823256]`
  这说明双 FIP payload 被按“前半包/后半包”拆分时，两路都混入了 FIP1 高值和 FIP2 低值。
- 23:02:58 日志出现：
  - `Filter disabled`
  - 后续 `display_range=[439,442]`
  在错误拆分后，降采样抗混叠低通会把交替出现的高低两路平均到约 `430` 附近。

问题定位：

1. 定点缩放位数错误。
   - 当前现场设备实际输出更符合 Q40.24，而不是旧文档中的 Q32.32。
   - Q32.32 会把设备端数值缩小 256 倍。

2. 双 FIP payload 拆分方式错误。
   - 当前设备发送顺序为采样点交织：`FIP1[0], FIP2[0], FIP1[1], FIP2[1]...`。
   - 旧软件按连续块拆分：前 1,000,000 点当 FIP1，后 1,000,000 点当 FIP2。
   - 因此两路软件数据都混有 FIP1 和 FIP2，幅值被后续低通/降采样拉到中间值。

3. 每秒起点尖跳。
   - FIP TCP 当前每秒发送一个大包，所以 View 页表现为每秒替换一包时域数据。
   - 信号滤波器和降采样抗混叠滤波器使用 IIR 状态；旧初始化直接使用 `sosfilt_zi`，没有乘以首样本。
   - 当输入存在大 DC 量或配置切换后，首点会被当作阶跃输入，产生首点瞬态。
   - 错误拆分时高低两路交替进入同一路数据，也会进一步放大包起点处的异常。

修复内容：

- `src/fip_tab1/fip_tcp_server.py`
  - FIP 定点解码从 `raw_int64 / 2^32` 改为 `raw_int64 / 2^24`。
  - 日志新增 `fixed_q=Q40.24`，方便现场复核协议缩放。
- `src/fip_tab1/fip_tab1_manager.py`
  - 双 FIP payload 改为交织拆分。
  - 新增 `FIP_SPLIT comm=... layout=interleaved ...` 日志，打印每一路 FIP 的首值和范围。
- `src/processing/signal_filter.py`
  - IIR 滤波器首次处理数据时，按首样本初始化滤波状态。
- `src/processing/downsampling.py`
  - 降采样抗混叠 IIR 首次处理数据时，按首样本初始化滤波状态。

验证：

- Q40.24 缩放验证：
  - `3316069512861 / 2^24 = 197653.145365`
  - `478403643438 / 2^24 = 28515.079226`
  与设备端 `194000` 和 `26300` 处于同一量级。
- 交织拆分合成测试通过：
  - FIP1 显示中位数约 `194002.41`。
  - FIP2 显示中位数约 `26300.39`。
  - 两路不再同时落在 `430` 附近。
- IIR 初始状态测试通过：
  - 常量输入 `194000` 经 decimate 后首点仍为 `194000`。
  - bandpass 滤波常量输入首点接近 `0`，不再出现大阶跃尖跳。

复测关注点：

- 新日志应出现 `fixed_q=Q40.24`。
- 新日志应出现 `FIP_SPLIT ... layout=interleaved`。
- FIP1/FIP2 的 split range 应分别接近设备端两个量级，而不是两路都覆盖高低全范围。
- 若 UI 滤波器设为 `none`，显示值应接近设备端原始工程量。
